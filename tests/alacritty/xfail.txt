# cursor home.  Alacritty 852e971 term/mod.rs decaln() only fills cells, so its
# golden leaves the cursor in place and preserves later E cells incorrectly.
# https://vt100.net/dec/ek-vt520-rm.pdf#page=170
decaln_reset
# This recording sends DECSET 3 without first enabling xterm mode 40.  Xterm
# 410 defaults the c132 resource to false and gates every DECCOLM side effect,
# including clearing, on screen->c132.  Shitty targets xterm-256color and keeps
# that default.  Alacritty 852e971 does not resize but unconditionally resets
# margins and clears the grid, which is the golden behavior asserted here.
# https://github.com/ThomasDickey/xterm-snapshots/blob/master/charproc.c
# https://github.com/alacritty/alacritty/blob/852e971cddfabe222d2d5bcda466e130f53af207/alacritty_terminal/src/term/mod.rs#L792

# Xterm 410 screen.c ClearCells() ORs TERM_COLOR_FLAGS into every erased cell

# scrolling retain both the current red foreground and default background.
# These Alacritty goldens instead give those blanks the default foreground.
# The pixels are identical, but their internal-cell oracle is not the
# xterm-256color model Shitty implements.
# https://invisible-island.net/archives/xterm/xterm-410.tgz
