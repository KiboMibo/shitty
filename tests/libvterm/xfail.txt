# Exact fixture IDs whose supported upstream golden assertions differ.
# Libvterm's raw parser callback canonicalizes 7-bit C1 forms such as ESC C
# into a `control 0x83` callback.  Zutty's diagnostic parser trace preserves
# the actual grammar production as `escape C`; both reach the same terminal
# control semantics, but the two private callback APIs are not identical.
# ECMA-48 section 5.3 defines ESC Fe as the 7-bit representation of C1.
# https://ecma-international.org/publications-and-standards/standards/ecma-48/
02parser.test
# This old decoder fixture accepts F7 BF BF BF as U+1FFFFF.  RFC 3629 limits
# UTF-8 to four-byte encodings through U+10FFFF, so Zutty correctly emits
# replacement characters.  Its per-maximal-subpart replacements for C0 80 C1
# BF also need not match libvterm's legacy grouping of those invalid bytes.
# https://www.rfc-editor.org/rfc/rfc3629#section-3
# https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-3/#G7404
03encoding_utf8.test
# These fixtures explicitly assert libvterm's implementation limit of five
# combining marks ("Spare combining chars get truncated").  Unicode grapheme
# clusters have no fixed code-point limit; Zutty intentionally retains the
# complete cluster, so its richer cell cannot equal this truncated oracle.
# https://www.unicode.org/reports/tr29/
10state_putglyph.test
# Two libvterm expectations differ from xterm.  For IL, xterm 410 util.c
# InsertLine() explicitly calls set_cur_col(ScrnLeftMargin), while the fixture
# keeps column 1.  For DECRQSS after DECSCA 2, xterm misc.c reports canonical
# `0"q` for either erasable state (0 or 2) and `1"q` only when protected; the
# fixture instead requires the non-canonical input spelling `2"q`.
# https://invisible-island.net/archives/xterm/xterm-410.tgz
13state_edit.test
# Libvterm resets all G0..G3 sets to ASCII and invokes G1 into GR.  DEC/xterm
# instead initialize G0/G1 to ASCII, G2/G3 to the user-preferred supplemental
# set, GL=G0 and GR=G2.  Xterm 410 resetCharsets() contains those assignments
# explicitly; its ctlseqs also describes ASCII plus DEC Supplemental as the
# initially mapped GL/GR halves.  The LS1R/LS2R/LS3R expectations in this
# fixture therefore cannot serve as an xterm-compatible oracle.
# https://invisible-island.net/archives/xterm/xterm-410.tgz
14state_encoding.test
# When a resize grows the page while autowrap is pending, libvterm's on_resize
# converts its phantom state into an ordinary cursor one column to the right.
# Xterm 410 ScreenResize changes max_col and clamps/restores cur_col but never
# clears or materializes `screen->do_wrap`; the next graphic still takes the
# normal wrap path.  Zutty follows xterm, so the fixture's row-0 column-80
# continuation is intentionally not produced.
# https://invisible-island.net/archives/xterm/xterm-410.tgz
16state_resize.test
# Libvterm hard reset emits cursor-blink=true, while xterm's cursorBlink
# resource defaults to false; Zutty uses that xterm default.  The fixture also
# expects URXVT 1015 button values 0/3 as if they were SGR 1006 values.  Xterm
# ctlseqs specifies that URXVT prints the same X10 button encoding as a decimal
# integer, and button.c retains the X10 +32 offset for URXVT (only SGR subtracts
# it), producing 32/35 as Zutty does.
# https://invisible-island.net/archives/xterm/xterm-410.tgz

# For `e` plus U+0301 followed by REP, libvterm repeats the complete grapheme.
# Xterm 410 CASE_REP checks CharWidth(lastchar) > 0 and ignores REP when the
# immediately preceding character is a zero-width combining mark.  Zutty
# follows xterm; the fixture therefore expects an extra cell which must not be
# produced.  The fixture also clamps `REP 1000` at the right edge.  ECMA-48
# defines REP as repeating the preceding character Ps times, without a
# line-boundary exception, and xterm 410 CASE_REP loops for the complete count
# through its normal wrapping `dotext` path.  Zutty therefore wraps and keeps
# repeating instead of leaving the following `b` at row 1, column 0.
# https://ecma-international.org/publications-and-standards/standards/ecma-48/
