Шрифтовый заход (бывшие пункты 2, 3, 23, 32, 44) — план согласован по аудиту
конкурентов (foot, kitty, alacritty, ghostty, wezterm, contour, windows-terminal,
xterm, vte, konsole, iterm2, rio):

- Отдельного dw-шрифта нет ни у одного современного терминала; правило «ровно 2×»
  не делает никто (xterm при несовпадении продолжает с флагом). Пустую клетку при
  полном отсутствии глифа не показывает никто, кроме foot.
- Ф1. -dwfont умирает, -font становится повторяемым. Fontpack держит упорядоченный
  список фейсов: первый задаёт метрики клетки, остальные — запасные; в хвосте —
  вендоренные шрифты (JetBrains Mono Nerd Font, Noto Color Emoji, Noto Emoji), они
  же — последний FontResolver (терминал больше не может не стартовать из-за шрифта).
  Кодоген кладёт данные шрифтов в .h на этапе сборки.
- Ф2. Выбор фейса по покрытию: faceFor(cp) — ленивый перебор фейсов по cmap
  (FT_Get_Char_Index / CTFontGetGlyphsForCharacters) с кэшем cp→face; для кластера
  фейс обязан покрыть все кодпоинты (ZWJ и variation selectors при матчинге
  пропускаются). Это чинит и уход индийских кластеров в CJK-шрифт (бывший п.23).
- Ф3. Подгонка вместо валидации: fallback-фейс рендерится движком в размер, где
  advance == N×cellWidth; если высота строки фейса больше cellHeight — размер
  уменьшается и контур пере-рендерится (мы растр не скейлим; исключение — растровые
  эмодзи, там ресемпл). Итоговый размер кэшируется на (фейс, N). Центрирование в
  боксе. Любая подгонка логируется один раз на шрифт.
- Ф4. Полное отсутствие глифа — рисуем полую рамку сами (kitty-стиль), пустых
  клеток не бывает (бывший п.32-частично).
- Ф5. Переполнение глиф-кэша: собрать уникальные глиф-ключи по окну+истории,
  пересоздать атлас размером count×2 (кап 65536 слотов из-за упаковки координат +
  байтовый потолок), сбросить ссылки, full damage — глифы набегают лениво.
  Вытеснение по поколениям в штатном режиме остаётся как есть.
- Ф6. Синтетический bold/italic, когда фейса нет: FT_GlyphSlot_Embolden +
  shear-матрица на FreeType; обводка + матрица на CoreText.

🟠 Средняя серьёзность

16. PtyOutputQueue без верхней границы — решено не чинить (по указанию).
22. В кодовой базе пять UTF-8-декодеров — сведение к одному не сделано (строгость plt-декодера починена отдельно).
29. Headless-поллер no-op — решено не делать (исключено ранее вместе с plt-переделкой headless).

🟡 Низкая серьёзность

33. Double-width lead без continuation-ячейки читает не тот атлас (render_vk.cpp, appendSource в materializeUpdates).
36. CoreText/FreeType паритет: разная обработка missing glyph, метрики округляются по-разному (сойдётся по мере шрифтового захода).

Недоделки

47. DECDHL: GPU-путь делает scale-and-clip (правильная модель — как conhost/xterm), reference-рендер кропит вместо удвоения; полный паритет — отдельная работа. Из аудита конкурентов: kitty/ghostty/foot/alacritty/VTE не реализуют DECDHL вовсе, эталон — xterm и Windows Terminal (растеризация 2x + клип половин + трансформация декораций).
48. Underline на DECDHL рисуется в обеих половинах; по DEC/conhost подчёркивание должно попадать только в нижнюю (следствие scale-and-clip декораций вместе с глифом).
49. Курсор на continuation-ячейке невидим — dw-рендеринг, в отдельный заход вместе со шрифтами.
51. DECAC: текстовая часть (Ps1=1) реализована; фреймовая (Ps1=2) сознательно игнорируется — как в xterm (единственная не-Windows реализация), DEC-фрейма в терминале нет.
52. DECDMAC/DECINVM: макро-хранилище сознательно не реализовано (вектор усиления/инъекции; VTE отказывает «for security reasons»); DECMSR (DSR 62) отвечает нулевым местом — как xterm, VTE, iTerm2 и contour.
53. S8C1T сознательно не влияет на ответы: 8-битные C1 (0x80–0x9F) — невалидный UTF-8; все современные UTF-8-only терминалы (kitty, foot, ghostty, wezterm, alacritty, mintty) игнорируют его и всегда отвечают 7-битно. Соответствующие esctest-кейсы остаются в xfail.
55. Fuzzing-конфигурация — не трогать (по указанию).
56. Захардкоженные Unicode-таблицы (VS15/VS16/viramas) — генератора по-прежнему нет (комментарий поправлен, utf8proc запинен на ≥2.9).

Улучшения (перф)

64. Цветной атлас наследует сетку mask-атласа (слоты общие): 16 МБ бюджета маски дают 64 МБ RGBA при первом emoji; лечится отдельным глиф-кэшем с собственным слот-неймспейсом для цветных глифов (шейдер уже ветвится по типу глифа) — отложено.
66. В color-пути глифы грузятся до трёх раз (общая FT_Library сделана).
