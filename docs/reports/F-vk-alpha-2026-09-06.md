# F-vk-alpha: `-backgroundOpacity` на Linux

Ветка `fix/F-vk-alpha` от `origin/master` = `cad8d7df`.
Вся работа сделана на `arch-mac` (Arch Linux x86_64, ядро 7.2.3, GeForce GTX 770M
через NVK / Mesa, gcc 16 и clang 22.1.8), в worktree `~/Projects/wt-fvk`.
Пометки: **[и]** — измерено здесь, **[п]** — прочитано в коде, **[в]** — выведено.

## Что было сломано

**[п]** `RendererImpl::backgroundOpacity()` в `lib/shitty/render_vk.cpp` возвращал
`100` безусловно. Комментарий при нём называл причину верно: swapchain создавался
через `selectCompositeAlpha()`, а тот перебирал режимы в порядке
`OPAQUE, PRE_MULTIPLIED, POST_MULTIPLIED, INHERIT` и брал **первый** поддержанный —
то есть практически всегда `OPAQUE`. При `OPAQUE` альфа-канал отбрасывается, и
премультиплицированный цвет дал бы не прозрачный фон, а **тёмный**.

**[п]** Вся остальная арматура уже стояла на месте (`T10`): очистка кадра идёт через
`backgroundAlphaFromPercent()` + `premultiply()` (`render_vk.cpp:1785`),
push-константа — через `packPaneBackground(..., backgroundOpacity())`, шейдер
`render.comp` пишет премультиплицированный цвет (`storeAtAlpha`, строки 660, 799–824).
Не хватало ровно двух вещей: попросить у swapchain composite alpha и перестать врать в
геттере.

**[в]** Отсюда же следует, что задача не про новую математику цвета: три рендерера
уже считают одинаково, расходился только один возврат.

## Что показывает поверхность (критерий 2)

**[и]** Отдельная проба (`/tmp/vkprobe.c` на `arch-mac`, `VK_EXT_headless_surface` —
та же поверхность, которую берёт теневой рендерер, `render_vk.cpp:593-600`):

```
device 0: GeForce GTX 770M (NVK GK106) (api 1.2.354)  supportedCompositeAlpha=0x3 [ OPAQUE PRE_MULTIPLIED ]
device 1: llvmpipe (LLVM 22.1.8, 256 bits) (api 1.4.354) supportedCompositeAlpha=0x3 [ OPAQUE PRE_MULTIPLIED ]
```

`0x3` = `OPAQUE | PRE_MULTIPLIED`. **Выбран `VK_COMPOSITE_ALPHA_PRE_MULTIPLIED_BIT_KHR`.**

**[в]** `POST_MULTIPLIED` сознательно не поставлен вторым после `PRE_MULTIPLIED`, а
оставлен позади `OPAQUE`: он просит композитор домножить на альфу **второй раз**, то
есть кадр под него пришлось бы писать «прямым» цветом — вторая цветовая конвенция,
расходящаяся с референсным рендерером, ровно в том месте, куда тесты паритета не
смотрят. Поверхность, дающая только его, получает непрозрачный путь и предупреждение:
картинка не прозрачная лучше, чем картинка неправильная.

## Правка

`lib/shitty/render_vk.cpp`, 65 строк вставлено / 27 удалено:

1. `selectCompositeAlpha()` — `PRE_MULTIPLIED` первым, `OPAQUE` вторым; порядок
   остальных сохранён. Выбор **не зависит от значения опции**: при `100` альфа и так
   `255`, режим не меняет ни пикселя, зато перезагрузка конфига, опускающая
   `backgroundOpacity`, застаёт цепочку, которая уже умеет это показать.
2. `SwapchainResources::compositeAlpha` — режим, с которым цепочка реально создана.
3. `RendererImpl::backgroundOpacity()` перестала быть `static` и отвечает по живой
   цепочке — той же формы, что `MetalRendererImpl::backgroundOpacity()`
   (`render_metal.mm:963`), которая спрашивает живой слой, а не опцию:
   ```
   if (chain == nullptr || chain->compositeAlpha != VK_COMPOSITE_ALPHA_PRE_MULTIPLIED_BIT_KHR) {
       return 100;
   }
   return composer.opts->backgroundOpacity;
   ```
4. Откат озвучен. В `createSwapchain()`, один раз на рендерер (`opaqueSurfaceWarned`),
   при `backgroundOpacity != 100` и непремультиплицированном режиме:
   ```
   shitty: -backgroundOpacity has no effect here; this Vulkan surface offers no
   premultiplied composite alpha, so the window stays opaque
   ```
   Форма — как у предупреждения `-backgroundBlur` при `100` (`options.cpp:1521`),
   через `composer.brand->identifier()`, поэтому в `pt` строка нейтральна.

`README.md`: два абзаца про `-backgroundOpacity` описывали ровно противоположное
поведение («deliberately not honoured», «reports an opacity of 100 unconditionally») —
переписаны. Заодно поправлена фраза «no compiler and no GPU has seen it» про
Vulkan-путь: файл теперь собран и прогнан на Linux, но только на однопанельных кадрах.

**Оффскрин-путь проверяем.** **[п]** Теневой рендерер тестов паритета не «без
swapchain»: `render_vk.cpp:593` создаёт настоящую `VkSurfaceKHR` через
`VK_EXT_headless_surface`, и дальше идёт тот же `createSwapchain()` с тем же
`selectCompositeAlpha()`. **[и]** Это подтверждено мутацией №2 ниже: перестановка
порядка режимов ломает именно тесты паритета. Точка остановки «премультипликация в
оффскрине непроверяема» не наступила.

## Обнаружено

- **NVK живой и достаточный.** `GeForce GTX 770M (NVK GK106)`, Vulkan 1.2.354 —
  теневой рендерер поднимается на нём и на `llvmpipe`; обе поверхности дают
  `PRE_MULTIPLIED`. **[и]**
- **`./build test` на этой машине не доходит до конца.** Останавливается на
  `3470/3512`: `unit_tests --group=4 --group-count=20 --threads=1` падает на
  `lib/shitty/pty_ut.cpp:961` (`WIFSIGNALED`-проверка). Тот же бинарь целиком, одним
  процессом, даёт `OK: 948` и `EXIT=0`. Отказ есть и **до** правки, к ней отношения не
  имеет, но означает: критерий «`./build test` зелёный» здесь непригоден так же, как на
  машине командира, и по другой причине. **[и]**
- **Первый снятый эталон набора был испорчен моим окружением.** Без
  `SHITTY_EMBED_EXAMPLE_BINARY` (и без построенной цели `example`) набор даёт 43
  лишние ошибки в `test_embed_example`. Переменная стоит в `build.py:1382` под
  условием `if example is not None` — на Linux это не None. Эталон переснят. **[и]**
- **Чего не хватает для визуальной проверки.** Сессия — `tty`: ни Wayland, ни X, ни
  `grim`, ни `weston`. Значит проверено **содержимое кадра** (побайтово против
  референса), но **не** то, как композитор его показывает: что окно на настоящем
  Wayland-компоновщике действительно просвечивает, здесь измерить нечем. Отдельно не
  измерено, какие `supportedCompositeAlpha` отдаёт **Wayland**-поверхность Mesa (у
  headless — `0x3`); если там окажется что-то без `PRE_MULTIPLIED`, сработает откат с
  предупреждением. **[и] / [в]**
- **Порядок в `selectCompositeAlpha` был единственным местом, где отказ был
  невидим.** Функция существовала, звалась на каждом создании цепочки, перебирала все четыре
  режима и выглядела правильной; неверен был только порядок. Гвардов на порядок
  предпочтений нет и, вероятно, быть не может — ловит это только паритет. **[в]**
- **`test_gpu_smoke.GpuSmokeTest` и `VulkanBlitSmokeTest` — два наблюдателя одного
  места**, оба были красны до правки и оба зелены после; ни один не был красным по
  унаследованной причине. Место покрыто (в смысле `R6-test`). **[и]**
