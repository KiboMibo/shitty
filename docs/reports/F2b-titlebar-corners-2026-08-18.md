## 1. Вторая половина I7 — `applyTitlebarColor()` больше не затирает прозрачность

**Диагноз (из отчёта приёмки):** `window.backgroundColor` — одно свойство AppKit с двумя владельцами без арбитража. `WindowImpl::requestCornerRadius()` (`platform_cocoa.mm`, F2) ставит его в `clearColor`, чтобы скруглённые углы контентной вью показывали рабочий стол. `CsdTabsUi::applyTitlebarColor()` (`ui_csd_tabs.mm`) запускается сразу после создания окна (`createCsdTabsUi()` идёт следом за `createWindow()` в `application.cpp`) и при `transparentTitlebar` безусловно перезаписывает то же свойство непрозрачным цветом фона терминала. За скруглёнными углами оказывается залитый прямоугольник — тот самый артефакт «квадратные уши», против которого написан комментарий `requestCornerRadius()`.

**Правило, которое уже записано в `renderContext()` (F2, `c0e38a20`):** у свойства — один владелец. Реализовал так: `applyTitlebarColor()` пропускает запись в `window.backgroundColor` ровно при том же условии, при котором `requestCornerRadius()` вообще очищает окно (`quick && quickCornerRadius > 0`) — то есть отдаёт владение свойством корневому фичи скругления, когда обе опции активны одновременно. Полоса титлбара в этом случае тоже становится прозрачной вместе со всем остальным, чего не заливает контент — это согласуется с образом «плавающей скруглённой панели», а не противоречит ему. Полоска вкладок (`ShittyTabBarView`) при этом продолжает перерисовываться в любом случае — её `drawRect:` читает `opts->bg/fg/cr` напрямую, не зависит от того, кто сейчас владеет фоном окна.

### Проверено измерением, не рассуждением

Собрал временную инструментальную сборку (добавил `fprintf` сразу после развилки, печатающий `window.opaque`, `window.backgroundColor.alphaComponent` и вычисленное условие пропуска; **не закоммичено**, убрано перед коммитом, `git diff` после отката пуст):

| Конфигурация | `opaque` | `backgroundColor.alphaComponent` | Пропуск сработал |
|---|---|---|---|
| `transparentTitlebar=true` + `quickCornerRadius=12` (обе опции) | `0` | `0.000000` | **да** — окно осталось прозрачным, углы покажут рабочий стол |
| только `transparentTitlebar=true` | `1` | `1.000000` | нет — сплошная заливка не изменилась, поведение прежнее |
| только `quickCornerRadius=12`, `transparentTitlebar` выключен | — | — | код `applyTitlebarColor()` вообще не доходит до этой точки (гейт `!composer.opts->transparentTitlebar` срабатывает раньше) — правильно, никакой регрессии |

Это не скриншот (Screen Recording не выдан этому окружению — ограничение, зафиксированное во всех предыдущих волнах), а **реальное значение свойства AppKit на живом окне**, что и есть функциональное доказательство: раз `alphaComponent == 0`, слой `masksToBounds` контентной вью физически не может показать ничего кроме прозрачности в этой точке. **Собственно визуальный результат (правда ли рабочий стол виден по углам, нет ли артефактов рендеринга) — по-прежнему требует человека.** Что смотреть: включить оба конфига разом, посмотреть на четыре угла терминальной сетки — должен быть виден рабочий стол/то, что за окном, а не залитый прямоугольник цвета фона терминала; сравнить с тем же конфигом без `quickCornerRadius`, где залитый прямоугольник (нормальный титлбар в цвет терминала) — ожидаемое поведение.

## 2. I5 — строка про сброс кадра в обоих конфигах

Решение `A6` требует явно: «Сброс — удалением файла (и это документируется)». Способ существовал в коде (`quick_frame_store.h`'s комментарий), но нигде не был виден пользователю. Дописал в оба конфига под `quickRememberFrame`, в существующем стиле (обычный комментарий после `# CLI:`-строки, сама `# CLI:`-строка не тронута — формат `# CLI: -имя — описание` с настоящим em dash сохранён идентично):

```
# CLI: -quickRememberFrame / +quickRememberFrame — Remember the quick-terminal window's manually set position and size across shows.
# State is kept next to this config file, at shitty-quick-frame in the
# same directory; delete that file to forget the saved frame and fall
# back to quickGeometry.
quickRememberFrame = false
```

(`bin/pt/pretty.toml` — то же самое, но `pretty-quick-frame`, брендовое имя.)
