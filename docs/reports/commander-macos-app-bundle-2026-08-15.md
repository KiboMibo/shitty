## Что получилось

`dev/make_app.sh` — скрипт, упаковывающий уже собранные бинари `st`/`pt` в
macOS-бандлы `Shitty.app` и `Pretty.app`. Ничего не компилирует: бинарь
копируется как есть, рядом кладутся `Info.plist` и `.icns`, собранный из
`shitty.svg`/`pretty.svg`, в конце ставится ad-hoc подпись.

Зачем это нужно. Терминал уже полноценное Cocoa-приложение
(`ext/plt/platform_cocoa.mm:852` — `NSApplication` + `ActivationPolicyRegular`),
но распространяется голым бинарём, и код это компенсирует в рантайме: иконка
Dock ставится вручную (`platform_cocoa.mm:1088`), имя в меню берётся из
`argv[0]`, то есть пользователь видит `st`. С бандлом приложение запускается из
Finder, Spotlight и Dock, а имя и иконка приходят из `Info.plist`.

Как пользоваться — раздел `## Install` в `README.md`.

## Ключевые решения по ходу

| Решение | Почему |
|---------|--------|
| `/coding-plan` пропущен | одна задача в одну волну; плановая машина дороже самой работы |
| Проверочная волна урезана до QA | нет продакшн-кода, данных и секретов; тесты и секьюрити-ревью shell-скрипта упаковки не дают выигрыша |
| Бинарь для проверки взят из `brew install pg83/tap/{shitty,pretty}` | локальная сборка требует `ragel` и Homebrew-LLVM (~2 ГБ); скрипт упаковки от источника бинаря не зависит |
| Третий круг приёмки вместо остановки после второго | оба вердикта были жёлтые, а не красные; лимит «двух кругов» относится к красным |
| Подпись только ad-hoc | нотаризация требует Developer ID — это решение пользователя, не командира |

## Оговорки

- Проект **не собирался локально ни разу**: `./build st pt` падает на отсутствии
  `ragel`, Homebrew-LLVM тоже не установлен. Все проверки шли на бинарях из тапа
  автора. Скрипт от источника бинаря не зависит, но связка «свежая сборка →
  упаковка» вживую не прогонялась.
- В третьем круге QA не смог перечислить реальные пункты меню (`osascript`
  потерял Accessibility-доступ, ошибка -1719); видимое имя подтверждено через
  `displayed name`. Полная проверка меню сделана в первом круге, и диф после неё
  генерацию `CFBundleName`/`CFBundleDisplayName` не трогал.
- `shellcheck` в окружении недоступен — квотирование проверялось чтением и
  живыми прогонами, включая путь с пробелом.
- Проверки делались только на этой машине (Apple silicon, macOS 15). На Intel и
  на других версиях macOS скрипт не гонялся.
- Для проверки в систему поставлены формулы `pg83/tap/shitty` и
  `pg83/tap/pretty`; исполнитель также выполнил `brew link --overwrite pretty`,
  чтобы развести коллизию с `tcl-tk`. Это изменение состояния Homebrew на
  машине, не репозитория.
