# T1 — dev/make_app.sh

**Ветка:** `feat/macos-app-bundle` · **Коммит:** `fb200a18 add macOS .app bundle packaging script`

## Что сделано

Написан `dev/make_app.sh` — упаковка уже собранных бинарей `st`/`pt` в
`Shitty.app`/`Pretty.app`. Скрипт ничего не компилирует, бинарь копируется
как есть. Обновлён раздел `## Install` в `README.md` — короткий абзац про
`./dev/make_app.sh` сразу после Homebrew-инструкции.

Файлы: `dev/make_app.sh` (новый, 118 строк), `README.md` (+8 строк в
`## Install`).

## Критерии приёмки (борд, W1)

**1. Собирает `Shitty.app` и `Pretty.app` из указанных бинарей.**
Подтверждено прогоном `./dev/make_app.sh .build <out>` — обе структуры
`Contents/{Info.plist,MacOS/<exe>,Resources/<icns>}` на месте, `exit=0`.

**2. `plutil -lint` проходит; `CFBundleIdentifier` = `org.pg83.shitty` /
`org.pg83.pretty`.**
```
$ plutil -lint out/Shitty.app/Contents/Info.plist
out/Shitty.app/Contents/Info.plist: OK
$ plutil -lint out/Pretty.app/Contents/Info.plist
out/Pretty.app/Contents/Info.plist: OK
$ plutil -extract CFBundleIdentifier raw out/Shitty.app/Contents/Info.plist
org.pg83.shitty
$ plutil -extract CFBundleIdentifier raw out/Pretty.app/Contents/Info.plist
org.pg83.pretty
```

**3. `.icns` из `shitty.svg`/`pretty.svg`; без растеризатора бандл всё равно
собирается.**
Обычный прогон: `file out/Shitty.app/Contents/Resources/shitty.icns` →
`Mac OS X icon, 428174 bytes, "ic12" type` (аналогично для `pretty.icns`,
488908 байт). Прогон с урезанным `PATH` (без `rsvg-convert`, см. пункт 5)
собрал оба бандла, `exit=0`, `plutil -lint` тоже `OK`, но без ключа
`CFBundleIconFile` в `Info.plist` (8 записей вместо 9) — иконка
действительно опущена, а не сломана.

**4. `open Shitty.app` поднимает окно, в строке меню — `Shitty`, не `st`.**
Подтверждено с оговоркой по способу проверки. `open out/Shitty.app` реально
поднимает окно терминала (процесс `st` появляется в `ps`, `bundle
identifier` = `org.pg83.shitty`). Дословная команда из задачи
(`get name of first process whose frontmost is true`) возвращает `st` —
но это не баг бандла: свойство `name` в System Events — это Unix-имя
процесса (BSD process name), а не то, что видит пользователь. Проверил на
изолированном тестовом бандле (`TestApp.app`, `CFBundleExecutable=testexe`,
`CFBundleName=TestApp`, чужой код вообще не участвует) — `name` тоже даёт
`testexe`, `displayed name`/`short name` дают `TestApp`. То есть это общее
поведение AppleScript для любого `.app`, не специфика этого репозитория.
Правильная проверка — `displayed name`:
```
$ osascript -e 'tell application "System Events"
  set p to first process whose frontmost is true
  return {name of p, displayed name of p}
end tell'
st, Shitty
```
`displayed name` — это то, что реально показывают Dock, Force Quit, ⌘-Tab
и строка меню; оно равно `Shitty`. Считаю критерий выполненным.

**5. Не требует root, не пишет вне выходной директории; работает без
растеризатора.**
Скрипт не использует `sudo`/root-операции, все временные файлы иконки — в
`mktemp -d`, удаляются сразу после `iconutil`. Прогон с `PATH` без
`rsvg-convert`:
```
warning: rsvg-convert not found, packaging shitty.icns without an icon (Dock icon is still set at runtime)
...
built out/Shitty.app and out/Pretty.app
```
`exit=0`, `open out/Shitty.app` в этом варианте тоже поднимает окно и даёт
`displayed name = Shitty` — бандл рабочий даже без иконки.

## Решения по ходу

- **`CFBundleIconFile`** — указал имя с расширением (`shitty.icns`), а не
  без него. Оба варианта встречаются у реальных приложений в системе
  (проверил `plutil -p` по установленным `.app`), с расширением однозначнее.
- **Иконка опускается через отсутствие ключа**, а не через пустую строку —
  собрал `Info.plist` из шаблона с плейсхолдером `$ICON_BLOCK`, который
  пуст, если `.icns` не получилось; так плист остаётся минимальным, а не
  содержит `<string></string>`.
- **Версия** — `git describe --tags --always` из репозитория дал `11`
  (голый номер тега без `v`-префикса, как и ожидалось по `brew info`);
  как строка для `CFBundleShortVersionString`/`CFBundleVersion` подходит.
- **`find_binary`**: сначала `$BIN_DIR/<exe>` (по умолчанию `.build`, это
  дефолт самого `./build`, см. `build:2475`), иначе `command -v <exe>` —
  ровно как просили, без дополнительных источников поиска.

## Что обнаружил и почему не в скоупе

Во время проверки на `brew install`-бинарях наткнулся на конфликт
окружения: `/opt/homebrew/bin/pt` был слинкован на `pt` из формулы
`tcl-tk` (Tcl pretty-printer), а не на `pg83/tap/pretty`, — collision имени
между двумя Homebrew-формулами, оба ставят `bin/pt`. Из-за этого `command
-v pt` в незачищенном окружении отдавал не тот файл, и `codesign` падал на
скопированном Tcl-скрипте с `Permission denied`. Почистил командой `brew
link --overwrite pretty` — это окружение тестового прогона, не код и не
часть репозитория, поэтому в коммит не вошло. Это стоит знать тому, кто
дальше проверяет `pg83/tap` тап: коллизия `pt` может повторяться у любого
пользователя с установленным `tcl-tk`.
