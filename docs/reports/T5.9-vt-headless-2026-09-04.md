# T5.9. Апстримный `vt_headless` целиком — и почему целиком не берётся

**Дата:** 2026-09-04 · **Задача:** `T5.9`, волна 6 плана `docs/plans/2026-08-29-upstream-merge.md` · **Ветка:** `feat/T5.9-vt-headless` от `68d04998` · **Коммит:** `bc02d5e0` · **Вердикт:** `ЧАСТИЧНО — задача в поставленной формулировке неисполнима`

Взять апстримный `lib/vterm/vt_headless.{h,cpp}` целиком **нельзя**, и это не вопрос вкуса: апстримное тело не компилируется против нашего `Vterm`. Ниже это показано тремя независимыми фактами уровня компилятора. Сделано то, что от задачи не зависит: снят мёртвый `#include`, закрывший одно из четырёх нарушений границы `lib/vterm`, и исправлены комментарии, обещавшие замену, которой не будет.

`lib/shitty/vterm_headless.*` **уже нет** — файл переехал ещё `M6e` (`e659cf5c`), удалять нечего.

## 2. Три факта, из-за которых апстримный файл не собирается

### 2.1. `Vterm::create` у нас на два параметра длиннее

```
наш       lib/vterm/vterm.h:329
  static Vterm* create(ObjPool& owner, Composer& composer, VtGeometry& windowGeometry,
      const VtConfigSlot& config, VtCellExtras& extras, SmallObjAllocator& smallObjects,
      plt::Scheduler& scheduler, VtHost& host, const PaneGeometry& geometry,
      PtyHandle& pty, VtermTraceFactory* traceFactory);            // 11 параметров

апстрим   7e2a8e3e:lib/vterm/vterm.h:226
  static Vterm* create(ObjPool& owner, VtGeometry& geometry,
      const VtConfigSlot& config, VtCellExtras& extras, SmallObjAllocator& smallObjects,
      plt::Scheduler& scheduler, VtHost& host,
      PtyHandle& pty, VtermTraceFactory* traceFactory);            // 9 параметров
```

Апстримный `vt_headless.cpp` зовёт девятиаргументную форму. У нас её нет.

### 2.2. `Vterm::windowResized()` у нас не существует

```
$ grep -n "windowResized" lib/vterm/vterm.h lib/vterm/vterm.cpp lib/vterm/vt_host.h   ; EXIT=0
lib/vterm/vterm.h:283:    // only on activation would come back wrong. Upstream's windowResized()
```

Единственное вхождение — комментарий, объясняющий, что метод **заменён** на `paneResized(const PaneGeometry&)` (`vterm.h:291`, инвариант `A8`: «the window's grid is not this pane's»). Апстримный `HeadlessVtHost::resized()` состоит из вызова `terminal->windowResized()`.

### 2.3. Апстримную сигнатуру `VtermHeadless::create` зовёт продуктовый код

```
$ grep -rn "VtermHeadless::create" --include=*.cpp .                                  ; EXIT=0
lib/shitty/main.cpp:104:        VtermHeadless::create(composer, nullptr);        ← точка входа st
lib/shitty/pty_ut.cpp:663:      VtermHeadless::create(composer, nullptr);
lib/shitty/vt_headless_ut.cpp:1419: VtermHeadless::create(*composer, nullptr);
bin/main_fuzz/main.cpp:121:     VtermHeadless::create(*composer->pool, *composer->vtConfig.config, &capture, pty);
bin/core_perf/main.cpp:84:      VtermHeadless::create(*pool, *composer->vtConfig.config, nullptr, nullptr);
```

Возврат к апстримной сигнатуре чинит две нижние строки и **ломает три верхние**, включая `lib/shitty/main.cpp` — точку входа `st`. Ни один из трёх файлов не принадлежит `T5.9`, `T5.10` или `T5.11`.

### 2.4. План противоречит сам себе

Строка 371 плана, `T5.4`: «**`Vterm::create` с 10 аргументами**: `VtGeometry` на панель». То есть план не планирует возвращать `Vterm::create` к апстримным девяти **никогда** — он уменьшает 11 до 10. Одновременно `T5.9` требует, чтобы `vt_headless.cpp` звал девятиаргументную форму. Эти две строки несовместимы, и заметить это можно было только измерением.

**Вывод:** «взять апстримный `vt_headless` целиком» = «взять апстримный `Vterm`» = снять `A1`/`A8`, ради сохранения которых существует весь план. Останавливаюсь и говорю, как велено брифом.

## 3. Что было нашего и куда делась функция каждой части

Апстримная функция покрывает наше расхождение **в одном месте из четырёх**. Таблица — по кускам расхождения, а не по строкам: строки в нём не независимы.

| Наш кусок | Строк | Апстрим покрывает? | Куда делась бы функция |
|---|---|---|---|
| `HeadlessVtHost` целиком: объявление + 19 тел методов + список схем в `uriSchemeAllowed` | −130 | **Да, полностью** | `Composer::installVtHost()` (`composer.cpp:222`) ставит `ComposerVtHost`, реализующий те же 19 методов. `uriSchemeAllowed` там идёт через `composer.opts->uriSchemeAllowed()` — реальную разобранную опцию, а не зашитые `http`/`https`/`file`. Апстримный комментарий сам называет свой список «the parsed-option default»; у нас это и есть разобранная опция. **Здесь премиса брифа верна, и этот кусок уже выброшен — `M6c`/`M6d`, не мной.** |
| `CallHeadlessResize` / `CallHeadlessFontChanged` | +35 | **Нет** | Заменять нечем: они существуют ровно потому, что `HeadlessVtHost::resized()` звал `windowResized()`, которого у нас нет (§2.2). Выбросить = headless-терминал не узнаёт о ресайзе своей панели и о смене шрифта. |
| Арифметика `A1` в `create()`: `contentInsets()` + `gridPixelWidth/Height()` вместо `columns * cellPixelWidth` | +6 | **Нет** | Апстрим считает поверхность из голого числа клеток. Выбросить = опция `border` перестаёт действовать в headless, то есть `A1` нарушен именно в том пути, которым ходят `main_fuzz`, `core_perf` и весь `vt_headless_ut.cpp`. |
| Поля `geometry_`/`configSlot_`/`extras_` → `Composer* composer_`; вызов 11-аргументного `Vterm::create` с `composer` и `windowPane(composer)` | +5 / −3 | **Нет** | Непокрываемо в принципе: апстримной девятиаргументной формы в дереве не существует (§2.1). |
| Четыре `#include` из `lib/shitty` | +4 | частично | `options.h` оказался **мёртвым** — снят (§4). `composer.h`, `pane_layout.h`, `grid_geometry.h` — цена зависимости от `Composer`; `grid_geometry.h` закроется сам собой на `T5.2`, которая уносит арифметику по `Insets` в `lib/vterm`. |

## 4. Что сделано

Один коммит, `bc02d5e0` — `drop the dead options.h include from the headless core`.

- **Снят `#include "options.h"`** из `lib/vterm/vt_headless.cpp`. Файл не называет ни `Options`, ни точку разбора; `Insets`, единственный тип, ради которого включение было правдоподобно, объявлен в `composer.h:71`. Нарушений границы стало **7 вместо 8**, моих — **3 вместо 4**.
- **Исправлены три комментария**, обещавшие, что файл будет заменён апстримным целиком. На их месте — §2 этого отчёта в сжатом виде, в заголовке, где следующий читатель станет искать.

Расхождение с апстримом после:

```
$ git diff --numstat 7e2a8e3e HEAD -- lib/vterm/vt_headless.h lib/vterm/vt_headless.cpp  ; EXIT=0
74	143	lib/vterm/vt_headless.cpp
15	4	lib/vterm/vt_headless.h
```

`cpp`: **+76 → +74**. `h`: **+8 → +15**, и весь прирост — комментарий из §2. Говорю прямо: по числу строк заголовок разошёлся с апстримом **сильнее**, чем был. Это сознательный размен — семь строк комментария против того, чтобы следующий исполнитель `T5.9` потратил сессию, заново упираясь в `windowResized()`. Если ревью решит, что отчёта достаточно, комментарий снимается одной правкой.

## Обнаружено

**О1. `T5.9` в поставленной формулировке неисполнима, и план противоречит сам себе.** `T5.9` требует, чтобы `vt_headless.cpp` звал девятиаргументный `Vterm::create`; `T5.4` (строка 371) фиксирует, что `Vterm::create` остаётся десятиаргументным. Обе строки в одной таблице. Формулировку `T5.9` надо переписать: «привести `vt_headless` к апстримному настолько, насколько позволяет панельный `Vterm`» — что и сделано, — либо явно поставить отдельную задачу на снятие `A1`/`A8`, чего никто не хочет.

**О2. Оценка «17 строк» в плане и брифе занижена в пять раз** (+84/−147). Она, судя по всему, получена из `git diff --stat` по одному заголовку. Для остальных строк таблицы `T5.2 – T5.11` это повод перепроверить оценки тем же способом — `--numstat` по обоим файлам пары.

**О3. `T5.10` тоже, вероятно, близка к нулю.** Её критерий — «перенести pane-тесты на новый API через `host()`/`geometry()`/`extras()`». Эти три аксессора есть в обеих версиях, а сигнатура `create` не поменялась, поэтому `lib/shitty/vt_headless_ut.cpp` **компилируется и проходит без единой правки**: `unit_tests` зелёные, `OK: 950`. Бриф предупреждал, что этот файл может сломаться, — не сломался. Перед стартом `T5.10` стоит просто собрать `unit_tests` и посмотреть, осталась ли работа.

**О4. `pane_grid_guard` не читает `vt_headless.cpp` вовсе.** Он фильтрует `path.name.startswith("render")` (`build.py:1600`), то есть из четырёх «сканирующих» гвардов файл видят три. Это не дефект — `A9` про рендереры, — но формулировка критерия «четыре гварда, каждый доказан пробой в твоём файле» невыполнима буквально, и следующему исполнителю это стоит знать заранее.

**О5. Ловушка №5 из брифа подтвердилась на практике.** После `./build -k …` симлинков `.build/st_test`, `.build/pt_test`, `.build/toml_dump` в дереве **не существует** (`ls` → `No such file or directory`), а не «остались старыми». В свежем worktree отказ громкий; в дереве, где прогон уже был, он был бы тихим и дал бы чужие числа. Питоновский набор гонялся только после сборки без `-k`.

**О6. `uriSchemeAllowed` у нас строже апстримного, и это улучшение.** Апстримный `HeadlessVtHost` зашивает `http`/`https`/`file` и называет это «the parsed-option default»; `ComposerVtHost::uriSchemeAllowed` (`composer.cpp:210`) идёт в реальную опцию. То есть один из немногих кусков, где «выбросить наше» было бы регрессией, уже выброшен — но заменён на лучшее, а не на апстримное.
