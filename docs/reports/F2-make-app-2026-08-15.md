# F2 — сдвиг признака готовности бандла на `codesign`

**Ветка:** `feat/macos-app-bundle` · **Коммит:** `da4e453f tie make_app.sh cleanup to codesign, not Info.plist`

Исходная задача — `docs/reports/T1-make-app-2026-08-15.md`, первый круг фиксов —
`docs/reports/F1-make-app-2026-08-15.md`, приёмка второго круга —
`docs/plans/reviews/macos-app-bundle-R1-qa-round2.md`. Этот отчёт закрывает
единственную важную находку оттуда; предыдущие отчёты не трогал.

## Находка QA (round 2)

`cleanup()` считала бандл «готовым» по наличию `Contents/Info.plist`, а
`Info.plist` пишется раньше `codesign`. QA воспроизвёл сквозным сценарием
(не моком): положил в `BIN_DIR` настоящий `st` и настоящий `pt` из `tcl-tk`
(тот самый файл без права записи, `-r-xr-xr-x`, из коллизии, описанной ещё
в T1-отчёте), прогнал скрипт без подмены `PATH` — `codesign` реально упал
на `Pretty.app` с `Permission denied`, а в `$OUT_DIR` остался бандл с
`Info.plist`, чужим Tcl-скриптом вместо бинаря и иконкой — внешне
завершённый.

## Фикс

Ровно то, что предложил QA и утвердил team-lead: признак готовности сдвинут
с «есть `Info.plist`» на «дошли до конца, включая подпись» — `CURRENT_APP=""`
теперь обнуляется сразу после успешного `codesign -s - --force "$APP"` (по
аналогии с тем, как уже обнулялся `WORK=""` после `iconutil`), а условие в
`cleanup()` упрощено до `[ -n "$CURRENT_APP" ]`. Комментарий над `cleanup()`
переписан, чтобы не обещать больше, чем код гарантирует.

## Побочная находка, обнаруженная и исправленная в процессе проверки

При обычном прогоне (`./dev/make_app.sh .build <out>`, никаких аварийных
условий) скрипт после упрощения `cleanup()` до `&&`-цепочки стал завершаться
с `exit=1` вместо `exit=0`, хотя оба бандла собирались правильно
(`plutil -lint` — `OK`, подпись на месте). Причина: последняя команда в
`cleanup()` — `[ -n "$CURRENT_APP" ] && rm -rf "$CURRENT_APP"` — на успешном
пути (`CURRENT_APP` уже пустая строка) сама по себе возвращает `false`
(exit-код 1), а это была последняя команда в обработчике `trap ... EXIT`;
POSIX-шеллы отдают код выхода именно последней команды обработчика как
итоговый код выхода скрипта, если сама программа не позвала `exit` явно.
В версии F1 та же ветка была обёрнута в `if ... fi` без `else`, который на
ложном условии возвращает `0` — поэтому баг не проявлялся до этой правки.

Починил стандартным паттерном для `trap ... EXIT`: сохранить `$?` первой
командой обработчика и явно перевызвать `exit "$STATUS"` в конце —
```sh
cleanup() {
    STATUS=$?
    [ -n "$WORK" ] && rm -rf "$WORK"
    [ -n "$CURRENT_APP" ] && rm -rf "$CURRENT_APP"
    exit "$STATUS"
}
```
Без этого фикса задача не могла бы считаться закрытой — обычная успешная
сборка стала бы выглядеть как падение для любого вызывающего кода,
проверяющего код возврата (CI, `set -e` в другом скрипте). Нашёл это именно
требуемым в задаче «обычным прогоном», до коммита.

## Как проверено

1. **Главный сценарий QA — падение на `codesign`.** Собрал `BIN_DIR` с
   настоящим `st` и настоящим `pt` из `tcl-tk` (`-r-xr-xr-x`, без права
   записи):
   ```
   $ ./dev/make_app.sh <binmix> <out>
   .../Shitty.app: replacing existing signature
   .../Pretty.app: Permission denied
   exit=1
   $ find <out> -maxdepth 2
   <out>
   <out>/Shitty.app
   <out>/Shitty.app/Contents
   ```
   `Pretty.app` в выводе отсутствует полностью — раньше оставался с
   `Info.plist`, чужим бинарём и иконкой. `Shitty.app` (собрался первым,
   до падения) — рабочий, с валидной подписью.
2. **Обычный прогон.** `exit=0` (после фикса регрессии выше), `plutil -lint`
   — `OK` на обоих `Info.plist`, `CFBundleIdentifier` — `org.pg83.shitty` /
   `org.pg83.pretty`, `codesign -dv` — подпись на месте на обоих бандлах.
3. **Аварийный сценарий из прошлого круга (`iconutil` падает).** Подмена
   `iconutil` на всегда падающую версию, тот же способ, что в R1/F1:
   `exit=1`, `$OUT_DIR` пуст (`ls -la` — только `.`/`..`), в `$TMPDIR`
   (реальный, через `/usr/bin/find`, не shell-обёртку) не осталось ни
   одного `icon.iconset` — регрессии по находке 1 из R1 нет.

`sh -n dev/make_app.sh` — синтаксис ОК.

## Что осталось за рамками

Ничего сверх однострочной правки, которую попросили, плюс фикс
самостоятельно найденной регрессии по exit-коду — без него сама правка была
бы неполной. Флаги, конфиги, DMG — не добавлял.
