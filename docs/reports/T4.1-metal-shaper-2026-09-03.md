## 3. Как снят `PaneArenaMirror`

### 3.1 Что зеркало делало и почему это больше не нужно

Зеркало решало задачу «арены на панель»: у каждой панели был свой `Screen` со своей ареной, они лежали на устройстве встык в порядке отрисовки, и каждой панели надо было выдать базу и хвост. Пара «идентичность панели + поколение» была там **не для экономии, а от недоверия к нумерации**: комментарий `A3` (`render_arena.h:23-40` до правки) прямо объяснял, что счётчик поколений — неатомарный `++` по глобали, и одно совпадение чисел от двух экранов даёт «ничего не сдвинулось» для панели, чьи байты в другом месте.

После `a3712f4e` шейпер один на окно (`Composer::shaper`), арена одна на плоскость, а смещения полос, которые панель выдаёт, **уже** являются смещениями в этой общей арене. Все базы — ноль, `biasStrips` прибавляет ноль, идентичность сравнивать не с чем.

### 3.2 То, что зеркало прятало: цикл поколения был панельным

Это найдено при снятии, а не принесено из брифа.

`assignStrips()` крутила цикл `do { generation = spanGeneration(); ...одна панель...; } while (generation != spanGeneration())`. Пока арены были у панелей свои, это было верно: сбор арены панели 1 не мог сдвинуть полосы панели 0.

С единой ареной — может. Шейпинг панели 1 вызывает сброс, поколение уезжает, и полосы панели 0, уже разложенные по клеткам, указывают в байты, которых там нет. Панельный цикл этого не видит: он закрылся на панели 0 в старом поколении и больше к ней не возвращается.

В смерженном состоянии `M5` это частично гасилось самим зеркалом (панели рапортовали разные `used` и разные поколения, зеркало перезаливало), но **неверно**: панель 1 получала базу `used0` и смещалась `biasStrips` на неё, хотя её полосы уже были абсолютными. То есть промежуточное состояние было не «расточительно, но верно», как оценил `M5`, а «верно ровно до первого сбора арены посреди многопанельного кадра».

Снятие зеркала обязано было это закрыть, иначе оно бы это состояние узаконило. Отсюда `assignFrameStrips()`:

```cpp
u32 MetalRendererImpl::assignFrameStrips(const PaneUpdate* frame, size_t count) {
    if (composer.shaper == nullptr) {
        return 0;
    }
    u32 generation;
    do {
        generation = composer.shaper->spanGeneration();
        for (size_t index = 0; index < count; ++index) {
            const TerminalUpdate& update = frame[index].update;
            if (update.shapes == nullptr) {
                continue;
            }
            assignPaneStrips(update, panes[index].cellOffset);
        }
    } while (generation != composer.shaper->spanGeneration());
    return generation;
}
```

Цена — переделка кадра целиком в редком случае сбора, та же ограниченная цена, что всегда платила смена шрифта.

### 3.3 Что стало вместо зеркала

`render_arena.h` — 99 строк, из них 61 комментария:

```cpp
struct ArenaCopy { size_t from = 0; size_t to = 0; };

struct ArenaMirror {
    ArenaCopy plan(u32 generation, size_t used);
    void reset();
    u32 generation = 0;
    size_t uploaded = 0;
};

inline ArenaCopy ArenaMirror::plan(u32 frameGeneration, size_t used) {
    const size_t from = generation == frameGeneration && uploaded <= used ? uploaded : 0;
    generation = frameGeneration;
    uploaded = used;
    return {from, used};
}
```

Три решения, каждое записано в комментарии файла:

- **Флага «ещё ничего не отзеркалено» нет.** `reset()` обнуляет `uploaded`, а `from == 0` и есть «вся арена». Флаг был написан и удалён как мёртвый: он не менял ни одного ответа.
- **`uploaded > used` внутри одного поколения невозможен** (арена только растёт до полной смерти), поэтому это признак пропущенного поколения, и ответ — вся арена. Одно сравнение вместо копии за концом буфера.
- **`used()` у зеркала больше нет.** Размер буфера теперь берётся прямо из `shaper.spanMaskUsed()` — раньше `used()` суммировала по панелям, суммировать больше нечего.

Комментарий `A3` переписан. Он не выброшен: старый объяснял, почему нельзя упрощать до скаляра, новый объясняет, **чем эта причина заменилась** — допущение не исчезло, а сузилось до «шейпер один на окно», и следующий, кто заведёт второй шейпер, владеет этим файлом.

## 4. Сторож `rowIdentityCounter`

Такого теста не было — заведён.

**`Screen::RowIdentitiesNeverRepeatAcrossScreens`**, `lib/shitty/screen_ut.cpp:388`.

Два живых экрана, по две строки, каждая пишется дважды разным текстом; собираются восемь идентичностей из `viewRow(row).id`; утверждается, что ни одна не равна нулю и никакие две не равны между собой.

Почему именно так:
- **два экрана**, а не один — свойство межэкранное, изнутри одного экрана пер-экранный счётчик выглядит безупречно;
- **два прохода разным текстом** — чтобы «свежая идентичность на мутацию» не подтверждалась перезаписью строки тем же содержимым;
- **сравнение всех пар**, а не соседних — пер-экранная нумерация даёт совпадения именно «через экран».

Тест живёт в `screen_ut.cpp`, который **не** под `#if HAVE_FREETYPE` (в отличие от `span_shaper_ut.cpp`, который на macOS компилируется в 336 пустых байт — находка `M5` №3). Проверено: он присутствует в списке имён локального прогона.

### Замечание `M5` про `Р5` — учтено, но не подменяет сторожа

`M5` §7 предложил писать тест `Р5` не против пер-экранного счётчика, а против «шейперов больше одного на окно». Замечание верное, и оно **записано в комментарий `render_arena.h`** как то, что ломает зеркало теперь. Но:

- бриф просит именно сторожа `rowIdentityCounter`, и он заведён;
- эти два допущения независимы. Общий счётчик нужен даже при одном шейпере: шейпер кеширует строки по идентичности **и ничему больше** — ни экрана, ни панели в ключе нет. Два экрана с одинаковыми номерами дадут перепутанные строки при любом числе шейперов;

## 6. Обнаружено

### 6.1 Промежуточное состояние после `M5` было неверным, а не просто расточительным

`M5` §4.1 оценил механический перевод так: «Расточительно, но не неверно: `biasStrips` прибавляет каждой панели её базу, а общее поколение означает „арена сбросилась у всех“». Оценка опиралась на посылку «все панели рапортуют одинаковые `used` и одинаковое поколение».

Посылка держится ровно до **сбора арены посреди многопанельного кадра**. `assignStrips()` возвращала поколение, снятое после шейпинга **своей** панели, а `spanMaskUsed()` читался тут же — значит панель 0 и панель 1 могли отдать разные пары. Тогда зеркало выдавало панели 1 базу `used0`, а `biasStrips` смещал на неё полосы, которые уже были абсолютными смещениями общей арены. Результат — панель 1 рисуется чужими байтами.

Плюс второй, независимый: панельный цикл поколения не мог заметить, что сбор, вызванный панелью 1, обесценил полосы панели 0.

**Уровень: важная.** Не как упрёк `M5` — он честно сказал, что делает минимум ради зелёной сборки, — а как класс: **«механический перевод, оставленный до задачи-переводчика, может быть не нейтральным, а неверным в редком пути».** Условие проявления (сбор арены в кадре с двумя и более панелями) локальными тестами не достигается, поэтому цена ошибки — не красный тест, а редкий визуальный дефект. Следующим мержам стоит писать в отчёте не «расточительно, но не неверно», а «неверно вот в каком пути, задача N закрывает».

### 6.2 Работа `G9` по аренам в Vulkan устарела и уменьшилась

`docs/reports/G9-split-parity-2026-09-03.md:314` предписывает: `u32 stripGeneration` (`render_vk.cpp:252`) → «два `PaneArenaMirror` (маска и цвет), как `render_metal.mm:219-220`». `:389` называет `PaneArenaMirror` одной из двух «уже существующих и проверенных сущностей», готовых к переносу.

Обеих больше нет, и переносить надо не их. Более того: **скаляр `stripGeneration` в Vulkan сейчас уже правильной формы.** Один шейпер на окно — одна арена, одно поколение; для сплитов ему нужен `ArenaMirror` (то же одно поколение плюс `uploaded`), а не диапазоны на панель. Из оценки `G9` в 350–500 строк арены выпадают почти целиком.

Два комментария в `render_vk.cpp` (`:247`, `:2295`) продолжают предписывать снятую структуру. Файл мой бриф трогать запрещает, поэтому они оставлены как есть и передаются владельцу.

**Уровень: важная.** Отчёт `G9` — вход в задачу, которая ещё не сделана; без правки исполнитель будет искать `PaneArenaMirror` в дереве, где его нет, и заведёт диапазоны на панель, которые не нужны.

### 6.3 Флаг, который написался сам и оказался мёртвым

Первая версия `ArenaMirror` несла `bool mirrored`, чтобы отличать «ещё ничего не отзеркалено» от совпадения поколений. Он не менял ни одного ответа: `reset()` обнуляет `uploaded`, а `from = uploaded = 0` и есть «вся арена». Удалён до коммита.

**Уровень: мелкая**, но это узнаваемая форма: при переносе состояния из сложной структуры в простую поля переезжают по инерции вместе со своим смыслом, а смысл уже обеспечен чем-то другим. Дешёвая проверка — спросить у каждого поля, какой конкретный вызов даст без него другой ответ.

### 6.4 Арх-документ `A3` устарел, и это предсказано заранее

`docs/architecture/2026-08-18-panes-and-window-chrome.md` описывает `A3` как «арены диапазонами на панель» и ссылается на `PaneArenaMirror::used()` (`:426`) как на образец формы «сумма по живым панелям». Образца больше нет.

`docs/plans/reviews/upstream-merge-invariants.md:131,146` это ровно предсказал: «`T4.1` владеет удалением… иначе следующий читатель будет искать `PaneArenaMirror`, которого нет». Правку арх-документа я не делал: файл вне моих границ, и решение «`A3` устарел, а не нарушен» — архитектурное. **Уровень: мелкая**, но требует явного действия владельца арх-ревью.

### 6.5 Ложное число, которого критерий не ждал

Критерий 2 брифа требует `OK: 955` или больше. Задача на удаление структуры с собственными тестами такого критерия выполнить не может, а **выполнить его формально было легко** — дописать шесть любых тестов до 955. Это дало бы ровно тот сорт зелёного, который сессия ловит пятый раз.

**Уровень: мелкая, но методическая.** Числовой порог `OK:` работает как сторож против потери тестов только при неизменном предмете. Для задач-удалений вместо порога нужен **diff списка имён** (что и приложено): он ловит потерю теста и при падении числа, и при его росте.

## 7. Что осталось непроверенным

Названо явно, чтобы не считалось проверенным.

1. **Многопанельный сбор арены.** Главный путь, ради которого сделан `assignFrameStrips` (§3.2), локально не воспроизведён. Чтобы шейпер сбросился посреди кадра, надо переполнить бюджет арены на двух и более панелях; ни один тест дерева этого не делает, а `MetalPanes::DrawThreeGridsInOneFrame` укладывается в бюджет с запасом. Проверено только то, что цикл закрывается за одну итерацию. **Оракул на это не заведён:** для него нужен либо управляемый бюджет арены у `SpanShaper` (интерфейс его не даёт), либо стенд на несколько тысяч уникальных глифов в двух панелях. Это отдельная работа.
2. **Суита `SpanShaper` (14 тестов) локально не исполняется вовсе** — `span_shaper_ut.cpp` целиком под выключенным на darwin `#if HAVE_FREETYPE && HAVE_HARFBUZZ`, объектник 336 байт (находка `M5` №3, перепроверена). Всё, что она проверяет про поведение арены под сбросом, здесь не проверялось; страховка — только Linux-CI.
3. **Linux и gcc/libstdc++.** Правка компилировалась и гонялась только на macOS. Круг задетого кода узкий — `#include "render_arena.h"` есть ровно в двух файлах (`render_metal.mm`, `render_arena_ut.cpp`), а `render_metal.mm` вне darwin не собирается вовсе, — но `render_arena_ut.cpp` и `screen_ut.cpp` собираются везде. Шаблонов новый код не содержит, так что ловушка `CLAUDE.md` про неквалифицированный `forward` неприменима; тем не менее сборку под libstdc++ я не проверял и утверждать её не могу.
4. **`test_wide_ligature_overflow` на Linux.** Зелёный на macOS (критерий 3); на Linux падает по средовой причине (гвард «глиф-бомбы» во FreeType 2.14.3, апстримный `3c91f408` не смержен). Не проверялся.
5. **Гварды прямым запуском, минуя `./build`.** Ловушка «штамп из CAS» закрыта иначе: `pane_grid_guard` доказан пробоем на изменённом содержимом (§5, критерий 6), что заодно доказывает и то, что он реально исполнялся. Для остальных четырёх — только штампы через сборку.
6. **Производительность.** Снятие `biasStrips` убирает обход всех клеток панелей `1..n-1` за кадр (прибор волны 8 — `docs/reports/T10-splits-2026-08-20.md`). Измерений не делал: прибор требует сборки `-Dcoverage` и `llvm-cov`, а критерии этого не просили. Ожидание — строго не хуже; проверено не было.
