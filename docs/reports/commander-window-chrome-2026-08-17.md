## Что получилось

Две независимые возможности в macOS-сборке терминала, обе за опциями и обе
выключены по умолчанию:

1. **`transparentTitlebar`** — титлбар сливается по цвету с фоном терминала.
   Полоска вкладок переработана под слитый фон: активная помечается полосой цвета
   курсора снизу, неактивные приглушаются цветами, выведенными из палитры
   терминала, а не системными.
2. **`quick` + `quickHotkey`** — quick terminal: процесс стартует без окна, окно
   выезжает сверху по глобальному хоткею (дефолт `ctrl+grave`) поверх любых
   приложений, прячется по повторному чорду и при потере фокуса.

Как пользоваться — `shitty.toml` / `pretty.toml` и `./st -help`.

## Ключевые решения по ходу

| Решение | Почему |
|---|---|
| Сплиты панелей **не** включены в план | Разведка показала три волны и смену контракта `Renderer` в двух бэкендах плюс эталонном; автор проекта сам вынес сплиты за скоуп в дизайн-доке вкладок |
| Горизонтальный сплит в будущем — `cmd+shift+d` | `cmd+h` съедается системным пунктом меню `Hide`, до приложения не доходит |
| Прозрачный титлбар только «лайт», без `FullSizeContentView` | `borderPixels()` скалярный и симметричный, протянут через рендер, попадание мыши и headless-путь |
| Quick terminal — **режим единственного окна**, включается опцией конфига | Приложение создаёт ровно одно окно за запуск; два режима достигаются вторым конфигом |
| Окно **не остаётся недостижимым** при нерабочем хоткее — показывается обычным образом | Решение командира по находке S2: цена «непонятного окна» ниже цены «потерянной сессии» |
| S7 закрыта гейтами в `platform_cocoa.mm`, **не** в `VtermImpl::windowOperation` | Рекомендация проверяющего архитектурно лучше (одно место), но `vterm.cpp` вне скоупа плана — заход туда решение пользователя, не командира |
| W2 не стартовала параллельно с F1 | `visible()` реализуется в `platform_cocoa.mm`, которым владеет T2 — вопреки оценке проверяющего, что файлы не пересекаются |
| Отклонено предложение чинить контраст через `window.appearance` | Исполнитель показал, что это оставляет исходную болезнь (независимость от `opts->bg`), а проверяющий затем посчитал и **нашёл в своей же рекомендации изъян**: неактивный текст стал бы ярче активного |

## Общая верификация (командиром, на итоговой ветке)

```
./build -j 8 st pt                     → exit 0
./style.py                             → exit 0 (см. оговорку ниже)
./build test -k                        → 12 узлов, множество имён совпадает с эталоном
SHITTY_TEST_BINARY=$PWD/.build/st_test python3 -m pytest tst/test_config.py  → 20 passed
```

Эталон падающих узлов: **12 при не-ASCII активной раскладке, 11 при ASCII** —
отличается ровно `plt-tests.stamp`. Причина детерминирована: тест
`ShiftedPrintableKeepsBothLayoutLevelsOnRelease` ждёт `layoutCodepoint == 'a'`, а код
при Shift берёт layout из `[event charactersByApplyingModifiers:0]` — из **активной**
раскладки, где физическая `A` даёт «ф». Сверять **имена, а не счётчик**.

## Оговорки

- **Ни одна визуальная проверка не закрыта агентами.** TCC Screen Recording не
  выдан, `screencapture` падает; проверено исполнителями и командиром лично.
  Единственный визуальный дефект, найденный за весь план, нашёл **пользователь по
  скриншоту** — структурные проверки через Accessibility показывали зелёное.
- **CI проекта — шесть Linux-проверок; весь код этого плана ими не покрыт.**
  Linux-сборка новых заглушек локально не проверялась (машина macOS, IX-реалма нет).
  Проявится на первом пуше.
- `./style.py` полным прогоном по файлу **переписывает 116 файлов дерева** —
  существующий разрыв с любым доступным `clang-format`, воспроизводится и на чистом
  `master`. Командир наступил на эту ловушку при общей верификации и откатил;
  исполнители проверяли стиль по добавленным строкам (`clang-format -lines=`).
- `./build test -k` собирает **из рабочего дерева**, а не из коммита. Дважды за план
  параллельная работа портила измерения (фокус от чужих GUI-пробников; пересборка
  бинаря с чужими незакоммиченными правками). Оба раза поймал проверяющий, а не
  автор. **Вывод: параллельным исполнителям и проверяющим выдавать git worktree;
  агентам, которым нужен живой GUI, работать по одному.**
- Внешний `CGWindowListCopyWindowInfo`-пробник **деградирует под накопленной
  нагрузкой** (X кратны ширине экрана — артефакт Mission Control). Такие значения
  нельзя усреднять: сессию замеров надо перезапускать. Разобрано инструментированной
  сборкой.
- Роль `/coding-architect` не привлекалась: план не менял границ модулей и схем
  данных, все архитектурные развилки были закрыты разведкой и решениями пользователя.
- Дефект вероятностный (31% показов) был найден **не первым** кругом приёмки, а
  третьим — предыдущие круги проверяли состояние до коммита, внёсшего регрессию.
  Это цена того, что исправления шли поверх уже проверенного кода.
