# F8d — `[[symbolFont]]` на Darwin: два красных и один зелёный впустую

Ветка `wave/upstream-merge-w8d`, база `d3b9d466`. Правка одна: `tst/test_font_fallback.py`,
три декоратора. Продуктовый код не тронут.

Ниже **измерено** — снято командой на этом дереве; **прочитано** — взято из исходника;
**выведено** — рассуждение поверх двух первых.

| 2 | Питоновский набор | `Ran 6485`, `errors=14`, `failures=0`, `skipped=22`; было `failures=2`, `skipped=19` |

## 1. Что было

Три теста класса `FontFallbackTest` строят fontconfig-фикстуру и назначают
`[[symbolFont]]`. На этой машине `SHITTY_TEST_FONTCONFIG=0` — fontconfig
недоступен, и на Darwin шрифты резолвит Core Text. **Измерено** до правки:

```
test_symbol_font_range_beats_primary_coverage           ... FAIL
test_symbol_font_defaults_to_private_use_pictograms     ... FAIL
test_symbol_font_that_misses_the_range_leaves_it_alone  ... ok
```

Оба отказа сами по себе диагностичны:

```
FAIL: test_symbol_font_range_beats_primary_coverage
    self.assertFalse(has_ink(plain))
AssertionError: True is not false

FAIL: test_symbol_font_defaults_to_private_use_pictograms
    self.assertGreater(ink_weight(assigned), ink_weight(plain))
AssertionError: 26476 not greater than 26476
```

Первый падает **на `plain`** — то есть подсунутый фикстурой пустой первичный
шрифт до рендера не доходит вовсе. Второй показывает, что рендер с назначенным
`[[symbolFont]]` и без него даёт **в точности одинаковый** вес чернил.

## 2. Доказательство вырожденности третьего теста

Третий тест утверждает: `[[symbolFont]]`, чьё имя не резолвится в шрифт с нужным
покрытием, не съедает диапазон — обычный обход покрытия всё равно рисует `W`.
Утверждение — `assertTrue(has_ink(pixels))`.

**Измерено.** Тело теста прогнано тремя вариантами конфига на одном и том же
дереве и в том же окружении. Третий вариант — назначение, которое **попадает** в
диапазон реальным боксовым шрифтом, покрывающим `W`; на платформе, где механизм
работает, он обязан изменить глиф.

Проба: `scratchpad/probe_f8d.py` (вне дерева репозитория). Запуск:

```
SHITTY_TEST_BINARY=$PWD/.build/st_test \
SHITTY_EMBED_EXAMPLE_BINARY=$PWD/.build/example \
SHITTY_PRETTY_TEST_BINARY=$PWD/.build/pt_test \
SHITTY_TOML_DUMP_BINARY=$PWD/.build/toml_dump \
SHITTY_TEST_FONTCONFIG=0 SHITTY_TEST_PLATFORM=cocoa \
SHITTY_TEST_VERSION=$(python3 -c "from datetime import date; print(date.today().strftime('%Y.%m.%d'))") \
PYTHONPATH=$PWD/tst python3 .../probe_f8d.py
```

Вывод:

```
как в тесте (шрифт не резолвится) | 44x26 | sha1=7813e8b43395bc1007d94863773b43a28b2c637c | has_ink=True | assertTrue(has_ink) -> PASS
[[symbolFont]] убран целиком      | 44x26 | sha1=7813e8b43395bc1007d94863773b43a28b2c637c | has_ink=True | assertTrue(has_ink) -> PASS
назначен РЕАЛЬНЫЙ бокс на W       | 44x26 | sha1=7813e8b43395bc1007d94863773b43a28b2c637c | has_ink=True | assertTrue(has_ink) -> PASS
```

Три рендера **побайтно одинаковы** — один и тот же sha1 на всех пикселях кадра.

**Выведено.** Тест не отличает «шрифт назначен, но диапазон не тот» ни от «шрифта
нет вовсе», ни от «шрифт назначен и диапазон именно тот». Последнее — сильная
половина доказательства: слабый вариант (снять назначение) для отрицательного
теста прошёл бы и на здоровой платформе, а вот попадание в диапазон обязано было
поменять картинку и не поменяло. Значит на Darwin `[[symbolFont]]` не наблюдается
никак, и зелёный третьего теста не несёт сведений. Это девятая вырожденная
фикстура за мерж — по списку в `CLAUDE.md`, «Вырожденная фикстура: восемь случаев
и общий приём против них».

Заодно **измерено**, что вырожден не только `[[symbolFont]]`, но и сама фикстура
первичного шрифта: `assertFalse(has_ink(plain))` в первом тесте краснеет,
то есть `"Shitty Coverage Fixture"` подменяется Core Text ещё до всякого
назначения.

## 3. Правка

Три метода помечены тем же гвардом, что уже стоит на соседнем
`SystemFallbackTest` в этом же файле:

```python
    @unittest.skipIf(
        TEST_PLATFORM == "cocoa",
        "Core Text precedes the Fontconfig fixture on Darwin",
    )
```

**Форма выбрана поэлементная, а не отдельный класс с гвардом на классе**: три
затронутых теста перемешаны в `FontFallbackTest` с четырьмя, которые на Darwin
проходят честно, поэтому выделение класса потребовало бы переноса и переотступа
трёх тел — диффа, который следующий мерж апстрима почти наверняка сконфликтует;
декоратор же добавляет четыре строки перед каждым `def` и якорится на имени
метода, так что правки апстрима в остальной части класса сливаются без участия
человека.

`TEST_PLATFORM` уже импортирован в файле (строка 11) — новых импортов нет.

## 4. Сколько тестов стало пропускаться и почему именно три

**Три**, и ровно те, что опираются на `[[symbolFont]]` поверх fontconfig-фикстуры.
Причина у всех одна — Core Text опережает фикстуру, — и она же в формулировке
гварда. Оставшиеся четыре теста `FontFallbackTest` не тронуты: два эмодзи-теста
(`test_emoji_renders_in_color_out_of_the_box`, `test_zwj_cluster_...`) фикстуру не
строят вовсе, а `test_narrow_codepoint_falls_back_by_coverage` и
`test_codepoint_covered_nowhere_draws_a_box` проверяют только наличие чернил после
обхода покрытия — это верно и через подмену Core Text, и они зелёные по существу.

## 6. Почему это не увод красного

Красный значит «сломано». Здесь не сломано ничего: на Darwin фикстура не работает
по устройству системы, и никакая правка продуктового кода этого не меняет.
Пропуск говорит правду и виден в счётчике `skipped`; вечно красный тест
обесценивает весь список красных, вечно зелёный впустую — обманывает. Потеря
покрытия мнимая: покрытия `[[symbolFont]]` на Darwin не было, была его видимость,
и §2 это измеряет.

## 7. В отложенное

**Дарвиновский двойник для `[[symbolFont]]` по образцу `CoreTextSystemFallbackTest`.**
После этой правки покрытие `[[symbolFont]]` на Darwin равно нулю — и теперь это
видно в счётчике пропусков, а не спрятано за одним зелёным. Двойник должен
строить назначение поверх шрифта, доступного Core Text (как
`CoreTextSystemFallbackTest` обходится без fontconfig-подкладки, передавая
`with_fontconfig_fallback=False`), и опираться на различие рендеров, а не на
наличие чернил. Премисса внутри теста обязательна: сначала утвердить, что
`plain` и `assigned` различимы в принципе, и лишь потом проверять направление.
