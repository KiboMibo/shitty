## 1. Что сделано

Класс `ExampleConfigParityTest` в `tst/test_config.py`, три теста:

| Тест | Что утверждает |
|---|---|
| `test_both_brands_assign_the_same_option_keys` | множества присваиваемых ключей совпадают |
| `test_both_brands_assign_the_same_values_up_to_the_brand_name` | значения совпадают **с точностью до имени бренда** |
| `test_both_brands_document_the_same_options` | множества задокументированных имён опций совпадают |

Сравниваются **имена**, а не строки и не их число: разбор идёт в множество
ключей и в отображение «ключ → значение», поэтому перестановка строк и
переписывание прозаического комментария сторожа не трогают. Сообщение любого
отказа называет **имена поимённо и сторону**: `only in bin/st/shitty.toml:
[...]; only in bin/pt/pretty.toml: [...]`.

---

## 2. Сравниваю ли значения, и по какому правилу

**Да, сравниваю — все значения всех общих ключей.** Правило — не список
прощённых ключей, а подстановка:

```
BRAND_WORDS = (("Shitty", "Pretty"), ("shitty", "pretty"), ("SHITTY", "PRETTY"))
```

Значение из `shitty.toml` прогоняется через эту подстановку и обязано
совпасть со значением из `pretty.toml`. Для 56 ключей из 57 подстановка
ничего не меняет, и правило вырождается в обычное равенство; единственный
ключ, который сегодня различается, — `title = "Shitty"` против `"Pretty"`
**[измерено]**.

**Почему правило, а не список.** Список пришлось бы дополнять руками при
появлении каждой следующей брендозависимой опции — а «дополнить руками» и
есть тот самый шаг, который забывают, ровно та мина, против которой сторож и
заводится **[выведено]**. Правилу сопровождение не нужно.

**Почему оно не начнёт лгать на следующей опции** — разбор двух сторон:

- *Ложная зелень* (расхождение есть, тест молчит) требует, чтобы неверное
  `pt`-значение совпало с брендированным `st`-значением. Но брендированное
  `st`-значение — это и есть **правильное** `pt`-значение. Ложная зелень
  невыразима **[выведено]**.
- *Ложная краснота* возможна: если у брендов законно разойдётся значение
  **не** по имени бренда. Тогда тест краснеет и заставляет сказать об этом
  вслух — а это правильный режим отказа, а не поломка. Расхождение,
  оставленное молча, — как раз то, что мы ловим.

## 3. Что именно считается «ключом», и почему документация тоже

Разбор различает три вещи **[прочитано]**:

1. **Присваивания** — `^имя = значение`. Это то, что читает бинарник.
2. **Индекс документации** — две формы, которые файлы уже используют как
   данные: `# CLI: -имя ...` для всего, у чего есть командная форма, и
   `# имя — ...` для конфиг-онли (`import`, `symbolFont`). Первую форму уже
   разбирает существующий `test_example_config_documents_every_public_cli_option`
   (`tst/test_config.py:63` до правки) — то есть это не «комментарий», а
   индекс.
3. **Заголовки таблиц** `[...]` — их наличие в живом виде запрещено премиссой,
   см. §5.

Сравниваются **только имена** из индекса, не описания. Поэтому переписывание
текста описания расхождением не считается — это сознательный предел, и он
согласован с требованием «правка комментария не краснит».

**Зачем вообще индекс, если ключи и так сравниваются.** Потому что
единственное расхождение, живущее в дереве прямо сейчас, — именно строка
индекса, а не присваивание (§7). Сторож, который видит только присваивания,
доложил бы «всё чисто» о дереве, содержащем ровно ту мину, ради которой он
заведён **[измерено]**.

**Замкнутость цепочки.** Сторож сравнивает `pt` с `st`, а `st` уже привязан к
самому бинарнику существующим `test_example_config_documents_every_public_cli_option`,
который сверяет индекс `shitty.toml` с выводом `-help`/`-listres`. Так что
«обе стороны потеряли опцию одновременно» ловится не здесь, а там
**[выведено]**.

## 5. Премисса внутри теста — против вырожденной фикстуры

Приём `F7`: тест утверждает свои опорные величины **до** того, как сравнивать.
Здесь самый вероятный отказ — не неверный ответ, а **пустой**: два пустых
множества ключей сравниваются успешно.

Метод `parsed()` утверждает, прежде чем вернуть хоть что-нибудь:

- оба файла существуют и непусты;
- ни в одном нет **живого** заголовка таблицы TOML — разбор плоский, а
  таблица переопределяет область видимости всех ключей после себя; сегодня обе
  `[[symbolFont]]` закомментированы, и в день, когда одна оживёт, тест
  покраснеет с требованием научить разбор областям видимости, а не начнёт
  молча сравнивать ключи из разных таблиц как один;
- ни в одном файле ключ не присвоен дважды — иначе дубликат сложился бы в
  словарь один раз и потеря на одной стороне сравнялась бы с другой;
- оба разбора перевалили порог (20 при сегодняшних 57 присваиваниях и 79
  задокументированных именах) — порог, а не точное число, потому что числа
  меняет каждый апстрим;
- присутствуют три опорных имени (`fontsize`, `title`, `border`), на которые
  опираются другие тесты этого файла;
- **правило бренда несущее**: есть хотя бы один общий ключ, значения которого
  буквально различаются, и хотя бы один, который `rebrand()` действительно
  меняет. Без этого пустой `BRAND_WORDS` вечно докладывал бы чётность.

Проверено, что премиссы **срабатывают**, а не украшают **[измерено]**:

| Проба | Результат |
|---|---|
| `bin/pt/pretty.toml` опустошён | 3 красных, `... pretty.toml is empty` |
| разбор ослеплён (`if False:` вместо условия) | 3 красных, `0 not greater than or equal to 20 ... parsed too few assignments` |
| `BRAND_WORDS = ()` | 1 красный, `no differing value is touched by rebrand(), so BRAND_WORDS says nothing about how these two files differ` |

## 7. Находка: расхождение уже в дереве, и решать его не мне

`bin/st/shitty.toml:84` несёт

```
# CLI: -vulkanBlit / +vulkanBlit — Present through the offscreen blit path instead of direct storage writes; command line only.
```

а `bin/pt/pretty.toml` — **нет** **[измерено]**. Опция не брендозависима:
`lib/shitty/options.cpp:96` держит её в общей таблице, значит `pt -vulkanBlit`
принимается и просто не задокументирован для этого бренда **[прочитано]**.
Строка пришла в `shitty.toml` коммитом `92657e71` («Grow coverage where the
tests never reached») и в `pretty.toml` не приходила никогда **[прочитано]**.

Это ровно та мина, ради которой заведён сторож, — она уже в дереве.

**Чинить я её не стал: `bin/pt/pretty.toml` принадлежит идущей параллельно
`T1`, а моя граница — только `tst/test_config.py`.** Вместо этого имя записано
в `DOCUMENTATION_ALLOWANCE` по образцу `lib/vterm/check_includes.py`:

- ключ — **пара «файл + имя»**, а не счётчик, поэтому разрешено ровно это
  отсутствие и ничего больше: ни второе имя в том же файле, ни `vulkanBlit`,
  пропавший вместо этого из `shitty.toml`;
- ключ говорит, что его закрывает: добавить строку в `pretty.toml` и удалить
  запись;
- проверка на осиротевший ключ (проба 4) делает удаление обязательным.

**Решение командира:** закрыть строку в `pretty.toml` — правка на одну строку,
но файл в чужих руках. Как только она пройдёт, запись из разрешения надо
снять, и тест сам об этом скажет.

## 10. Чего сторож не проверяет — прямо

- **Текст описаний** в строках `# CLI:` и прозу вокруг них. Сравниваются
  только имена. Описание, переписанное в одном файле, расхождением не
  считается — сознательный предел ради требования «правка комментария не
  краснит».
- **Закомментированные примеры** (`# dump = ...`, `# quickCompanion = ...`).
  Отличить пример от прозы надёжно нельзя: в обоих файлах есть строка
  `# quick = true - but must not also set quickCompanion itself`, которая на
  разбор примера похожа и примером не является. Дыры это не оставляет: у
  каждой такой опции есть своя строка индекса, и её сравнивает третий тест
  **[выведено]**.
- **Потерю опции сразу с обеих сторон.** Это не работа сторожа чётности;
  `st`-сторону держит `test_example_config_documents_every_public_cli_option`,
  сверяя её с `-help` бинарника.
