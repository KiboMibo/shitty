- **Разведка:** `docs/research/2026-08-16-window-features-recon.md`
- **Предыдущая работа:** `docs/reports/commander-window-chrome-2026-08-17.md`
- **Ветка:** `feat/window-chrome-upstream`

## Контекст

Терминал `pg83/shitty` — **чужой апстрим**. Уже сделано и работает: `quick`,
`quickHotkey`, `quickGeometry`, `quickCompanion`, `transparentTitlebar`.

Ключевые факты кода (проверять перед правкой, дерево живое):

- `Renderer` (`lib/shitty/render.h`) — `update(const TerminalUpdate&)` и `repaint()`;
  кадр = одно обновление, рендерер презентует сам.
- `vterm.cpp` читает `composer.columns`/`composer.rows` **105 раз**.
- `Composer::borderPixels()` (`lib/shitty/composer.cpp:141`) — один `u16`, 37 мест
  в десяти файлах.
- `SessionSet` (`lib/shitty/session.h`) — плоский список; `activate(index)`
  деактивирует все остальные терминалы.
- `Screen` уже параметризован своими `columns`/`rows` — единственная часть,
  готовая к панелям без правок.

## Цель и критерии готовности

Готово, когда на macOS верно всё перечисленное:

1. Quick-окно: скруглённые углы, запоминание вручную заданных позиции и размера,
   фуллскрин по отдельному чорду.
2. Боковая панель вкладок справа, скрывается и показывается по `cmd+b`.
3. Оформление окна прячется и появляется по наведению мыши, **число строк сетки
   при этом не меняется**.
4. Сплиты: `cmd+d` делит панель вертикально, `cmd+shift+d` — горизонтально,
   панели живут внутри вкладок.
5. Без новых опций поведение **побитово прежнее**.
6. Производительность рендера на одной панели не ухудшилась — подтверждено
   замером, а не мнением.

## Вне скоупа

- Равномерные сетки панелей и произвольные раскладки — только бинарное дерево.
- Перетаскивание вкладок и панелей мышью между позициями.
- Синхронизация ввода между панелями (broadcast).
- Автоматический фуллскрин по альтернативному экрану — выбран ручной чорд.
- Wayland-реализация новых возможностей: заглушки, не реализация.
- Нотаризация, релизные действия.

## Архитектурные решения

Полностью — в арх-документе. Кратко то, что исполнитель обязан знать:

| ID | Решение |
|---|---|
| `A1` | `border` (опция пользователя) и резерв под хром — разные понятия; вводится `Insets{top,right,bottom,left}` и `Composer::contentInsets()` |
| `A2` | `Renderer::update` принимает **span из `PaneUpdate`**, не машину состояний `beginFrame/endFrame` |
| `A3` | Арены глифов — диапазонами на панель; **сплиты не включать, пока не измерена производительность** |
| `A4` | Панели живут внутри вкладок, бинарное дерево сплитов |
| `A5` | «Видима» и «в фокусе» — разные состояния `Vterm` |
| `A6` | Геометрия quick-окна — отдельный файл состояния с атомарной записью; сохранённое побеждает `quickGeometry` |
| `A7` | Ховер меняет только видимость; полоса резервируется постоянно. `cmd+b`, наоборот, законно меняет сетку |
| `A8` | `Vterm` получает свою геометрию полями экземпляра, не читает окно |

## Контракты

Фиксируются задачей **T1**, все последующие задачи используют как есть.

**Новые опции** (все `false`/пусто по умолчанию — поведение апстрима не меняется):

| Ключ | Вид | Дефолт | Смысл |
|---|---|---|---|
| `quickCornerRadius` | значение | `0` | Радиус скругления углов quick-окна в точках; `0` — выключено |
| `quickRememberFrame` | `NoArg` | `false` | Запоминать вручную заданные позицию и размер |
| `quickFullscreenHotkey` | значение | пусто | Чорд фуллскрина quick-окна; пусто — выключено |
| `sidebarTabs` | `NoArg` | `false` | Вертикальная панель вкладок справа |
| `sidebarWidth` | значение | `220` | Ширина панели в точках |
| `autoHideChrome` | `NoArg` | `false` | Прятать оформление, показывать по наведению |
| `panes` | `NoArg` | `false` | Разрешить сплиты панелей |

**Геометрия:**

```
struct Insets { u16 top; u16 right; u16 bottom; u16 left; };
Insets Composer::contentInsets() const;   // border + резервы хрома
```

**Единицы — backing pixels.** `borderPixels()` = `opts->border * contentScale`,
поэтому и `Insets` живёт в backing pixels. Опции, документированные в точках
(`sidebarWidth`, `quickCornerRadius`), **обязаны умножаться на `contentScale`**
при попадании в `Insets`. На Retina (`contentScale = 2`) буквальное чтение
«220 points» как 220 пикселей даст панель двойной ширины и двукратный промах
хит-теста мыши.

`borderPixels()` **сохраняется** для чтения опции, но не используется для
раскладки.

**Рендер (A2):**

```
struct PaneUpdate { Rect area; const TerminalUpdate& update; };
virtual bool update(stl::Span<const PaneUpdate> panes) = 0;
```

Существующая форма `update(const TerminalUpdate&)` остаётся тонкой обёрткой над
списком из одного элемента — headless-путь и текущие тесты не ломаются.

**Ограничение, проверенное приёмкой probe-компиляцией:** `PaneUpdate` содержит
ссылочное поле, поэтому неприсваиваем. `stl::Vector<PaneUpdate>` с `pushBack`
работает (контейнер копирует байтами), но заполнять заранее выделенный буфер
поэлементно нельзя. Для T8 это не помеха: список панелей собирается `pushBack`-ом,
переиспользование буфера — через `clear()` плюс `pushBack`. Ссылка сохранена
сознательно: соответствует `A2` и тексту плана.

**Раскладка (A4):** узел дерева — лист с сессией либо сплит
`{ Direction direction; float fraction; Node* first; Node* second; }`.
Точные имена фиксирует T9.

**Действия ввода:** новые `InputActions` — `ToggleSidebar` (`cmd+b`),
`SplitVertical` (`cmd+d`), `SplitHorizontal` (`cmd+shift+d`). Чорды всегда в
`defaultBindings[]`, но **обработчики не делают ничего, пока соответствующая
опция выключена** — так поведение по умолчанию остаётся прежним.

## W1 — контракт

### T1. Опции и контракты всего плана

- **Зависит от:** —
- **Волна:** 1
- **Файлы (владеет):** `lib/shitty/options.cpp`, `lib/shitty/options.h`,
  `bin/st/shitty.toml`, `bin/pt/pretty.toml`, `lib/shitty/test_mode.cpp`,
  `ext/plt/window.h`, `lib/shitty/composer.h`
- **Файлы (только читает):** арх-документ, `lib/shitty/composer.cpp`
- **Скилы:** `/coding-writer`

**Что сделать**

Завести все семь опций из раздела «Контракты» по накатанной цепочке проекта:
строка в таблице `options.cpp`, поле в `options.h`, разбор в
`OptionsParser::parse()`, строка документации в **обоих** конфигах, поле в
ответе `OPTIONS` (`test_mode.cpp`).

Объявить `struct Insets` и `Composer::contentInsets()` (объявление плюс
реализация, пока возвращающая симметричный `border` — то есть поведение не
меняется). Объявить `PaneUpdate` и новую форму `Renderer::update` **в виде
контракта**, не реализуя её в бэкендах — реализация в T8.

Опции пробросить в `plt::WindowOptions` там, где они нужны оконному слою.

**Почему всё сразу:** `options.cpp` и оба конфига — общие для всех семи фич.
Один владелец в первой волне убирает конфликт, из-за которого иначе пришлось бы
выстраивать задачи в цепочку.

**Критерии приёмки**

- `./build -j 8 st pt` собирается; `./build test -k` — базис по именам.
- `./st -help` показывает все семь опций.
- `SHITTY_TEST_BINARY=$PWD/.build/st_test python3 -m pytest tst/test_config.py`
  зелёный — то есть строки документации в обоих конфигах совпали по формату
  (**настоящий em dash**) и множеству.
- Запуск с каждой новой опцией не меняет поведения (они ещё ничего не делают).
- Поведение без новых опций **побитово прежнее**.

## W3 — фундамент отступов

### T4. Асимметричные отступы (A1)

- **Зависит от:** T1
- **Волна:** 3
- **Файлы (владеет):** `lib/shitty/composer.cpp`, `lib/shitty/render_metal.mm`,
  `lib/shitty/render_vk.cpp`, `lib/shitty/render_reference.cpp`,
  `lib/shitty/render.comp`, `lib/shitty/vterm.cpp` (только пересчёты
  «пиксель → ячейка»), `lib/shitty/vterm_headless.cpp`,
  `lib/shitty/application.cpp`, `lib/shitty/test_mode.cpp`
- **Файлы (только читает):** `composer.h`, арх-документ раздел `A1`
- **Скилы:** `/coding-writer`

**Что сделать**

Перевести раскладку со скаляра на `Insets` по решению **A1**. `Composer::resize`
считает колонки и строки из размера минус отступы **по сторонам**. Рендереры
кладут начало сетки в `(insets.left, insets.top)`, а не в `(border, border)`.
Шейдер `render.comp` получает начало сетки параметром вместо скалярного
`border` — **одна правка обслуживает оба бэкенда**, шейдер общий.

Пересчёты «пиксель → ячейка» в `vterm.cpp` (хит-тест ссылок, mouse-протокол,
границы автоскролла выделения) учитывают левый и верхний отступ.

Резервы хрома пока всегда нулевые — то есть **видимое поведение не меняется**.
Их выставят T5 и T6.

**Почему одной задачей:** правка широкая, но механическая и связная; разрезать
её — значит оставить дерево в состоянии, где часть кода считает по-старому.

**Критерии приёмки**

- Без новых опций рендер **побайтово прежний**: эталонные тесты рендера зелёные,
  `render_reference_ut` не изменился в поведении.
- Клик мышью попадает в ту же ячейку, что до правки (проверить на краях сетки).
- `./build test -k` — базис по именам не вырос.
- `borderPixels()` больше не используется для раскладки (проверить `grep -r`).
