# План: прозрачный титлбар и quick terminal

- **Дата:** 2026-08-17
- **Статус:** готов к исполнению
- **Цель:** добавить в macOS-сборку терминала две независимые возможности — прозрачный титлбар и quick-terminal-окно, всплывающее по глобальному хоткею.

## Контекст

`pg83/shitty` — терминал на C++ с платформенным слоем `ext/plt` (Cocoa на macOS,
Wayland на Linux). Разведка проведена и записана: **`docs/research/2026-08-16-window-features-recon.md`**.
Читай её перед началом любой задачи — там устройство окна, точные точки
подключения и обязательные правила проекта. Повторную разведку не заказывай.

Что важно знать сразу:

- Окно `PltWindow: NSWindow` создаётся в `ext/plt/platform_cocoa.mm:1121`, маска —
  чистая функция `cocoaWindowStyleMask()` (`:51-57`).
- `ui_csd_tabs.mm` подсаживает свою `NSView` **внутрь системного титлбара**
  (`:162-187`), заголовок при этом прячется.
- Прозрачности, уровней окна, `collectionBehavior`, глобальных хоткеев и метода
  «спрятать окно» в проекте **нет ни одного вхождения**.
- Приложение создаёт **ровно одно окно за запуск** (`application.cpp:565-580`),
  `Composer` держит единственные `window`/`renderer`.
- Сборка на macOS: `brew install ragel glslang spirv-cross`, затем `./build -j 8 st pt`.
  Apple clang достаточно, Homebrew-LLVM не нужен.
- **CI проекта — шесть Linux-проверок; macOS-код ими не покрыт вообще.** Всё, что
  делается в этом плане, проверяется только локально и руками.

## Цель и критерии готовности

Готово, когда на macOS верно всё перечисленное:

1. `st -transparentTitlebar` (и ключ в конфиге) даёт титлбар, слитый по цвету с
   фоном терминала; полоска вкладок остаётся читаемой; без опции вид не меняется.
2. Конфиг с `quick = true` даёт окно, которое стартует скрытым, всплывает по
   глобальному хоткею поверх любых приложений **включая чужой фуллскрин**,
   прячется по повторному хоткею и при потере фокуса.
3. Хоткей настраивается ключом `quickHotkey`, дефолт — `ctrl+grave`.
4. `./build test` зелёный, `./style.py` не находит нарушений, сборка Linux не
   сломана (в ней macOS-код не участвует, но общие файлы — да).
5. Поведение без новых опций **побайтово прежнее**.

## В скоупе

- Прозрачный титлбар в «лайт»-варианте: единый цвет, **без** `FullSizeContentView`.
- Quick-terminal-режим единственного окна процесса.
- Глобальный хоткей на Carbon `RegisterEventHotKey`.
- Три новые опции и их документация в обоих брендовых конфигах.

## Вне скоупа

- **Сплиты панелей.** Отложены сознательно: три волны, включая смену контракта
  `Renderer` в двух бэкендах. Решение на будущее зафиксировано:
  вертикальный сплит — `cmd+d` (клавиша свободна), горизонтальный — **`cmd+shift+d`**,
  потому что `cmd+h` съедается системным пунктом меню `Hide`
  (`platform_cocoa.mm:824-826`) и не доходит до приложения.
- Полный прозрачный титлбар с контентом под светофором — упирается в скалярный
  `borderPixels()`, протянутый через рендер, попадание мыши и headless-путь.
- Автоскрытие титлбара по ховеру — зависит от предыдущего пункта и несёт риск
  `SIGWINCH` на каждое движение мыши.
- Анимация выезда quick-окна — решение пользователя: без неё.
- Настраиваемые из конфига биндинги вообще (таблица `defaultBindings[]`
  вкомпилирована) — отдельная подсистема.
- Linux/Wayland-поведение новых опций: заглушки, не реализация.

## Архитектурные решения

| Решение | Почему | Что отвергли |
|---|---|---|
| Quick-режим включается **опцией конфига**, а не CLI-флагом | Выбор пользователя. Два режима одновременно достигаются вторым конфигом: `st -config ~/.config/quick.toml` | Второе окно в том же процессе — требует переделки `Composer` под несколько окон |
| Quick terminal — **режим единственного окна**, не новое окно | `application.cpp:565-580` создаёт ровно одно окно; `Composer` держит единственные `window`/`renderer` | — |
| Глобальный хоткей — Carbon `RegisterEventHotKey` | Не требует разрешения Accessibility и работает поверх фуллскрина; так делает Ghostty. `<Carbon/Carbon.h>` уже подключён (`platform_cocoa.mm:27`) | `CGEventTap` — требует Accessibility с диалогом, плохой обмен для терминала |
| Хоткей живёт в **отдельном macOS-only модуле**, а не в `ext/plt` | `ext/plt` — вендорный слой с собственной лицензией и README; чем меньше мы его трогаем, тем лучше. Образец — `ui_csd_tabs.mm`, подключается из `application.cpp:581-585` под `#if defined(__APPLE__)` | Правка `platform_cocoa.mm` под хоткей — расширяет диф в вендорном слое без нужды |
| Титлбар — **только цвет**, `FullSizeContentView` не включаем | Геометрия остаётся нетронутой: `borderPixels()` скалярный и симметричный, его протяжка — отдельный крупный кусок | Полный вариант — см. «Вне скоупа» |
| `activationPolicy` остаётся `Regular` | Меньше риска; окно остаётся в Dock и `cmd+tab` | `Accessory` (как в Ghostty) — прячет из Dock, но меняет поведение обычных запусков |
| Геометрия quick-окна фиксированная: верх активного экрана, вся ширина, 40% высоты | Каждая опция стоит 8 файлов и обязательную строку документации с em dash; без запроса не плодим | Опции позиции и высоты — добавим, если попросят |
| Все три опции по умолчанию **выключены** | Проект чужой; поведение по умолчанию не меняем | — |

## Контракты

Зафиксированы в W1, на них закладываются W2 и W3.

**Опции** (`options.cpp` таблица, `options.h` поля, оба `.toml`):

| Ключ | Вид | Дефолт | Смысл |
|---|---|---|---|
| `transparentTitlebar` | `NoArg` (bool) | `false` | Титлбар сливается по цвету с фоном терминала |
| `quick` | `NoArg` (bool) | `false` | Окно работает как quick terminal |
| `quickHotkey` | значение (строка) | `ctrl+grave` | Чорд глобального хоткея |

Имена ключей и стиль строк документации — **по соседям в таблице**
(`options.cpp:73-135`). Строка в обоих конфигах строго
`# CLI: -имя — описание` **с em dash**, иначе падает
`tst/test_config.py:52-73` (сверяет множества через `assertSetEqual`).

**`plt::WindowOptions`** (`ext/plt/window.h:90-110`) — три новых поля:

```
bool transparentTitlebar = false;
bool quick = false;
// геометрия quick-окна вычисляется бэкендом, в опциях не задаётся
```

**`plt::Window`** (`ext/plt/window.h:112-158`) — два новых метода:

```
virtual void requestHide() = 0;                 // orderOut:, наружу сейчас не выставлен
virtual void requestShowAt(ShowPlacement) = 0;  // показ без [window center]
```

`ShowPlacement` — перечисление с двумя значениями на сегодня: `Centered`
(текущее поведение `requestShow`) и `TopOfActiveScreen`. Точные имена и форму
согласует T1; W2/W3 обязаны использовать то, что T1 зафиксировала.

**Toggle quick-окна** — функция, которую модуль хоткея дёргает у приложения.
Сигнатуру объявляет T1 в заголовке нового модуля; T3 её реализует, T4
обеспечивает поведение окна.

скоупа**, отметь это комментарием.

Взаимодействие с `no-decorations` продумай: при отсутствии титлбара опция

## W3 — quick terminal

### T3. Глобальный хоткей

- **Зависит от:** T1
- **Волна:** 3
- **Файлы (владеет):** новый `ui_quick_hotkey.mm` и `ui_quick_hotkey.h` (имена
  согласуй с T1), `build.py`, `application.cpp`
- **Файлы (только читает):** `ui_csd_tabs.mm` (образец модуля), `input_remap.cpp`
  (парсер чордов), `options.h`, `ext/plt/window.h`
- **Скилы:** `/coding-writer`

**Что сделать**

Модуль по образцу `ui_csd_tabs.mm`: подключается из `application.cpp:581-585`
под `#if defined(__APPLE__)`, регистрируется в списке darwin-only `.mm`
(`build.py:654-658`). Внутри — регистрация Carbon-хоткея
(`RegisterEventHotKey` + `InstallEventHandler`) и разбор строки `quickHotkey`
в virtual keycode плюс Carbon-модификаторы (`cmdKey`, `optionKey`, …).

Разбор чорда: словарь модификаторов бери из `input_remap.cpp:121-131`
(`ctrl`/`control`, `shift`, `alt`/`opt`/`option`, `super`/`cmd`/`command`/`meta`),
имя клавиши — в virtual keycode (`kVK_*`, они уже доступны через
`<Carbon/Carbon.h>`, `platform_cocoa.mm:27`). `grave` обязан разбираться.

Хоткей регистрируется **только** при `quick = true`. Нераспознанный чорд —
внятная диагностика на stderr и работа без хоткея, а не падение.
Снятие регистрации при завершении обязательно.

Срабатывание хоткея переключает видимость окна через контракт из T1.
Приложение живёт на `CFRunLoopGetMain()` (`platform_cocoa.mm:887`) — Carbon-события
туда доходят штатно.

**Критерии приёмки**

- Без `quick = true` хоткей не регистрируется вовсе (проверь, что чорд работает
  в других приложениях как обычно).
- С `quick = true` нажатие `ctrl+grave` в **любом** приложении переключает окно.
- Мусорный `quickHotkey` даёт сообщение и не роняет процесс.
- Хоткей снимается при выходе: после `kill` процесса чорд снова свободен.
- `./build -j 8 st pt` и `./build test` зелёные; Linux-сборка не задета
  (модуль под `#if defined(__APPLE__)`, в `build.py` — в darwin-списке).
- `./style.py` чистый; в новом файле — **MIT-шапка** (`CONTRIBUTING.md:97-108`).

### T4. Quick-режим окна

- **Зависит от:** T1
- **Волна:** 3
- **Файлы (владеет):** `ext/plt/platform_cocoa.mm`
- **Файлы (только читает):** `ext/plt/window.h`, `options.h`, `application.cpp`
- **Скилы:** `/coding-writer`

**Что сделать**

При `quick = true`:

- уровень окна выше обычного (`NSStatusWindowLevel` либо `NSFloatingWindowLevel` —
  выбери и обоснуй комментарием);
- `collectionBehavior` с **`NSWindowCollectionBehaviorFullScreenAuxiliary`** —
  именно он даёт появление поверх чужого фуллскрина, плюс `CanJoinAllSpaces`;
- реализовать `TopOfActiveScreen`: верх экрана, на котором сейчас курсор, вся
  ширина `visibleFrame`, высота 40% от неё. Сейчас выбора экрана нет вовсе —
  `info()` берёт `window.screen ?: [NSScreen mainScreen]` (`:1308`);
- скрытие при потере фокуса — точка `windowDidResignKey` (`:196-199`) →
  `WindowImpl::focused(false)` (`:1597-1603`). Событие фокуса по-прежнему обязано
  доходить до терминала: не подменяй его, добавь поведение рядом.

Обычный режим (`quick = false`) обязан остаться **побитово прежним** — все
правки под условием.

**Критерии приёмки**

- После показа окно занимает верх экрана с курсором, во всю ширину, 40% высоты.
- Окно всплывает **поверх приложения, развёрнутого в фуллскрин**, и не уводит
  систему на другой Space.
- Потеря фокуса прячет окно; терминал при этом получает событие расфокуса как
  раньше (курсор перестаёт мигать — то же поведение, что у обычного окна).
- `quick = false`: старт, показ, ресайз, фуллскрин, вкладки — как до правки.
- Двухмониторная проверка: окно выходит на том экране, где курсор.
- `./build test` зелёный, `./style.py` чистый.


Ручные сценарии (никакой CI их не покроет):

1. Запуск без опций — вид и поведение прежние.
2. `-transparentTitlebar` — слитый титлбар, вкладки читаемы, окно таскается.
3. `quick = true` — старт скрытым, `ctrl+grave` показывает и прячет.
4. То же поверх приложения в фуллскрине.
5. То же на втором мониторе.
6. Выход из процесса — чорд снова свободен для системы.

## Риски и открытые вопросы

| Риск | Что делать |
|---|---|
| **`ctrl+grave` конфликтует с вводом** — в терминале это управляющий символ. Пользователь выбрал его дефолтом; альтернатива — `cmd+grave` (как Ghostty) | Дефолт меняется одной строкой в `options.cpp`. Если при живой проверке T3 окажется, что чорд мешает работе в шелле, вынести это в отчёт как находку, а не менять молча |
| Carbon-хоткей может не работать в **неупакованном** бинаре (запуск без `.app` в проекте поддерживается специально, `platform_cocoa.mm:1098-1119`) | T3 обязана проверить оба запуска: `./st` и через `Shitty.app` из `dev/make_app.sh` |
| `presentsWithTransaction` + синхронный `displayLayer:` могут дать мерцание при показе окна | Анимации нет — риск снижен; при мерцании фиксировать как находку |
| macOS-код **не покрыт CI проекта** | Всё проверяется локально и руками; в отчётах указывать это явно |
| Правки в `ext/plt` расширяют диф в вендорном слое | Модуль хоткея вынесен наружу; в `ext/plt` только контракт окна и quick-режим |

**Точки остановки — здесь агент обязан спросить человека:**

1. Понадобилось включить `NSWindowStyleMaskFullSizeContentView` или тронуть
   `borderPixels()` — это выход за скоуп в дорогую сторону.
2. Понадобилось править главное меню или `performKeyEquivalent:` ради чорда.
3. Понадобилось переделывать `Composer` под несколько окон.
4. Смена `activationPolicy` на `Accessory` — меняет поведение обычных запусков.
5. Любое изменение поведения по умолчанию (без новых опций).
