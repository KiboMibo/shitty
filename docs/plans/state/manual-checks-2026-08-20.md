# Визуальные проверки для человека: волны 2-4

Собрано из `panes-R2-qa-round4.md` (пункты 1-6), `panes-R4-qa.md` (что смотреть человеку) и
чеклистов `T5`/`T6`. Это всё, что **невозможно** подтвердить в этой среде: Screen Recording не
выдан, `CGWindowListCreateImage` в этой версии macOS удалён. Всё остальное по этим волнам
закрыто числами.

**Порядок неважен, но подготовка общая.**

## Подготовка

```sh
git worktree add /tmp/vis bb32752a && cd /tmp/vis && ./build -j 8 st st_test
mkdir -p /tmp/viscfg
```

**Первое, что проверить в любой из этих проверок — включена ли опция.** Все они выключены по
умолчанию: проект чужой апстрим, и поведение по умолчанию не меняется. `quickCornerRadius = 0`
означает «скругления нет» — это не дефект, а выключенная опция. Проверять на своём рабочем
терминале можно и удобно, но тогда опцию надо дописать в свой конфиг и перечитать его
(`SIGUSR1`), а не полагаться на то, что рецепт её выставил.

**Перед каждым прогоном:**

- **разблокировать экран** — на залоченном окно не становится key, файл состояния не пишется
  вовсе, AX отказывает (проверено кругом 4);
- **остановить свой quick-терминал**: `pgrep -fl "Shitty.app"` — иначе он заберёт чорд себе.

Чорд везде `cmd+shift+f12`: он существует в грамматике, в отличие от `f19`, который по ошибке
попал в один из отчётов (`I11`).

## Часть A. Quick-окно (волна 2) — четыре пункта

Запуск во всех четырёх — один и тот же:

```sh
SHITTY_FOR_TESTS=1 /tmp/vis/.build/st_test -config /tmp/viscfg/q.toml & kill -USR2 $!
```

`SIGUSR2` показывает и прячет окно — это отладочная точка входа, добавленная `F2c` специально
ради этих проверок; она есть только в тестовой сборке.

### A1. Скругление углов — видно ли его вообще

```sh
printf 'quick = true\nquickHotkey = "cmd+shift+f12"\nquickCornerRadius = 12\n' > /tmp/viscfg/q.toml
```

**Смотреть:** скруглены ли углы прямоугольника с текстом.

**Почему нельзя вывести из кода:** радиус ставится на `CAMetalLayer`, а `masksToBounds` на
металлическом слое работает не на всех конфигурациях. **Квадратные углы = фича не работает, и
это находка**, а не «показалось».

### A2. Тонировка титлбара — то, что вы просили после `F2b`

```sh
printf 'bg = "#2e3440"\nquick = true\nquickHotkey = "cmd+shift+f12"\nquickCornerRadius = 12\ntransparentTitlebar = true\n' > /tmp/viscfg/q.toml
```

**Смотреть три вещи:**

1. за скруглёнными углами виден **рабочий стол**, а не прямоугольник цвета фона;
2. полоса титлбара **того же цвета**, что терминал под ней, без шва;
3. полоса по-прежнему **таскает окно** и зумит по двойному клику, кнопки работают.

Все три подтверждены числами (цвет заливки совпал с `bg` до третьего знака, заливка не отвечает
на клики) — остаётся увидеть.

**Отдельно:** поменяйте `bg` в конфиге и пошлите `SIGUSR1` — полоса должна перекраситься сразу,
без перезапуска.

### A3. Мерцание при показе

Любой конфиг выше. Нажать чорд **10-15 раз не торопясь**.

**Смотреть:** мигает ли содержимое белым или чёрным в момент появления.

**Отдельно** с `quickRememberFrame = true` и уже сохранённым кадром: не мелькает ли окно на один
кадр в «неправильном» размере. После восстановления идёт пересчёт сетки — это самое вероятное
место для такого мелькания.

### A4. Скругление в фуллскрине и возврат углов

Конфиг из A2 плюс `quickFullscreenHotkey = "cmd+shift+f11"`. Показать окно, нажать
фуллскрин-чорд.

**Смотреть:** углы должны стать квадратными, просветов по углам экрана быть не должно. После
второго нажатия скругление должно **вернуться**.

Что ветка свёртки достижима и вызов исполняется — замерено кругами 2-4. Что это видно глазами —
только вы.

## Часть B. Боковая панель и автоскрытие (волна 4) — четыре пункта

Здесь обычный `st`, без тестовой сборки:

### B1. Панель вкладок — видна ли вообще

```sh
/tmp/vis/.build/st -sidebarTabs
```

**Смотреть:** видна ли вертикальная полоса вкладок вдоль **правого** края.

**Это главный пункт всей волны 4.** В логе есть строка `sidebar: tab list installed on the right
edge`, ширина сетки честно уменьшается (`tput cols` снят до и после) — но **порядок композиции
AppKit-вью над `CAMetalLayer` числами не проверяется**. Если полосы не видно при наличии строки
в логе — это тот самый риск, и лечится он переносом вью на `contentView.superview`.

### B2. Автоскрытие оформления

```sh
/tmp/vis/.build/st -autoHideChrome
```

**Смотреть:** появляется ли оформление при наведении на верхнюю полосу и исчезает ли при уходе
курсора.

Что сетка при этом **не шевелится** — доказано (десять циклов, `tput lines` не меняется).
Повторять не нужно, смотрите только на видимость.

### B3. Обе опции сразу, включая фуллскрин

```sh
/tmp/vis/.build/st -sidebarTabs -autoHideChrome
```

**Смотреть:** не наезжают ли панель и полоса оформления друг на друга **визуально**. Проверить и
в обычном окне, и в фуллскрине.

Геометрически они независимы — это проверено.

### B4. Клики

**Смотреть:** клик по вкладке переключает; клик по строке `+` создаёт вкладку; клик по вкладке,
когда оформление **показано** — не «проваливается» ли он в терминал сквозь трекер.

## Что это даст

- **A1 красный** → скругление не работает на этой конфигурации; чинится не в коде окна, а в
  слое.
- **A2 пункт 1 красный** → вернулась «квадратные уши», то есть регрессия `I7`.
- **A2 пункт 3 красный** → заливка титлбара перехватывает события, чего не должна.
- **B1 красный** → композиция над `CAMetalLayer`, известный риск с волны 4.
- Всё остальное зелёное → визуальная часть волн 2-4 закрыта, и в итоговом отчёте это будет
  сказано прямо.

## Чего в этом списке нет и почему

**Wayland/Linux.** Реализация `setCornerRadius()` и весь Vulkan-код **не проверялись
компилятором** ни исполнителями, ни кругами приёмки — кросс-компиляции здесь нет. Считать
непроверенным до первого Linux-прогона. Аудит директив (`darwin_call_guard`) появился и ловит
класс дефекта, который стоил волне 2 блокера, но **сборку он не заменяет**.

**Кросс-дисплейный сценарий.** Требует двух мониторов; сейчас подключён один. Механизм проверен
в форме «origin на экране, край свисает» и закреплён юнит-тестом с координатами вашей пары
мониторов, но живьём на двух дисплеях не переснимался с круга 3. Когда снова подключите второй:
перетащить окно **на границу** дисплеев, спрятать, показать — окно должно остаться на стыке, а
файл состояния после следующего скрытия — содержать ту же расстановку, а не подрезанную.
