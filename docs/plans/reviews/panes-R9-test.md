## 1. Шов виден. Измерен по всей цепочке, а не по половине

**Да, виден, и полоса цвета опции, а не фона панели.**

Сначала — что уже есть в волне и чего в ней не хватало. Отгружены два теста, и каждый меряет свою половину:

- `render_reference_ut.cpp:1141` `TheSeamBandIsPaintedIntoTheAirAndNotOverEitherGrid` — читает пиксели эталонного рендерера, но полосу **подаёт руками**: `PixelRect band{leftGridEnd, 0, air, ...}`, где `leftGridEnd` вычислен в самом тесте;
- `session_ut.cpp:2310` `TheSeamBandIsClampedToTheAirBetweenTwoPanesAtBothEnds` — проверяет геометрию того, что отдаёт `visibleSeams()`, но пикселей не видит.

**Стыка между ними нет.** Они встречаются на числе, которое каждый вычисляет для себя, — ровно тот разрыв покрытия «по шву между двумя наборами», который F9 сама описала в поправке к своему пункту 3. Полоса, которую отдаёт `SessionSet`, и полоса, которую красит рендерер, нигде не сверены друг с другом.

Поэтому мерил цепочку целиком: взял полосу из `visibleSeams()` настоящего `SessionSet`, отдал её эталонному рендереру вместе с прямоугольниками из `visiblePanes()`, прочитал пиксели. Границы воздуха вычислял **из `visiblePanes()` и `paneInsets()`**, а не константой.

```
R9PROBE seams=1
R9PROBE band x=37 w=6  air=[37,43) border=3/3
R9PROBE row 12: ..######..   ('#'=ink, '.'=not ink; window [35,45))
```

Полоса, которую отдаёт `SessionSet`, — `x=37, w=6`. Воздух между сетками — `[37, 43)`, тоже шесть пикселей. Совпадение точное, и картинка это показывает: два пикселя сетки, шесть пикселей чернил, два пикселя сетки. Ни одна ячейка не потеряна.

## 2. Зажим держит оба конца — развёртка по четырнадцати случаям

Мерил не два конца, а всю развёртку, одним зондом, через ту же полную цепочку. `inked` — сколько пикселей чернил попало в воздух, `onGrid` — сколько попало на **сетку** любой из панелей (это и есть то, ради чего зажим существует).

```
border=3  asked=0     air=6  seams=0 bandw=0  inked=0  onGrid=0  ............
border=3  asked=1     air=6  seams=1 bandw=1  inked=1  onGrid=0  ......#.....
border=3  asked=2     air=6  seams=1 bandw=2  inked=2  onGrid=0  .....##.....
border=3  asked=5     air=6  seams=1 bandw=5  inked=5  onGrid=0  ....#####...
border=3  asked=6     air=6  seams=1 bandw=6  inked=6  onGrid=0  ...######...
border=3  asked=7     air=6  seams=1 bandw=6  inked=6  onGrid=0  ...######...
border=3  asked=3000  air=6  seams=1 bandw=6  inked=6  onGrid=0  ...######...
border=1  asked=1     air=2  seams=1 bandw=1  inked=1  onGrid=0  ....#...
border=1  asked=2     air=2  seams=1 bandw=2  inked=2  onGrid=0  ...##...
border=1  asked=3     air=2  seams=1 bandw=2  inked=2  onGrid=0  ...##...
```

- **Верхний конец.** `asked=7` и `asked=3000` при воздухе 6 дают полосу 6; `asked=3` при воздухе 2 даёт 2. Полоса шире воздуха не съедает **ни одной** ячейки: `onGrid=0` во всех четырнадцати случаях.
- **Нижний конец.** `asked=1,2,5` при воздухе 6 дают полосу ровно такой толщины, а по краям воздуха остаётся фон — видно по точкам вокруг решёток внутри окна.
- **Центровка.** При `asked=1` чернила стоят посередине воздуха, а не прижаты к одной панели. При нечётной толщине полоса смещена на полпикселя вправо (`asked=5`: `....#####...`) — это следствие целочисленного `width / 2` и не выводит полосу за воздух.

**Мутация M-A** (зажим снят: `seamWidth()` возвращает запрошенное как есть) ломает это ровно там, где должна:

```
border=3  asked=7  air=6  seams=1 bandw=7  inked=6  onGrid=1  ...#######..
onGrid == 0 failed
```

Один пиксель чернил лёг на сетку правой панели. **Отгруженные тесты эту мутацию тоже ловят** — краснеют `TheSeamBandIsClampedToTheAirBetweenTwoPanesAtBothEnds` и `WithNoBorderThereIsNoAirAndSoNoSeamAtAnyWidth`, `OK: 934, ERR: 2`. То есть зажим закреплён не только моим зондом.

## 3. `border = 0`: согласен, не дефект — и сказано там, где прочтут

**Измерено, а не принято на слово.** Четыре случая из той же развёртки:

```
border=0  asked=0     air=0  seams=0 bandw=0  inked=0  onGrid=0  ......
border=0  asked=1     air=0  seams=0 bandw=0  inked=0  onGrid=0  ......
border=0  asked=4     air=0  seams=0 bandw=0  inked=0  onGrid=0  ......
border=0  asked=3000  air=0  seams=0 bandw=0  inked=0  onGrid=0  ......
```

Воздуха нет, `visibleSeams()` не отдаёт **ни одной** полосы ни при какой толщине, включая максимальную, и на поверхность не ложится ни одного пикселя чернил.

**Согласен, что это не дефект.** Сетки соседних панелей при нулевом бордюре соприкасаются; любая полоса легла бы поверх чьих-то ячеек, а это хуже невидимого шва. Отказ здесь — единственное поведение, которое не портит текст.

**И сказано там, где человек это прочтёт** — проверил обе строки справки (`options.cpp:111-112`):

- `paneDividerColor`: «Needs `-border` above 0 to have anywhere to paint»;
- `paneDividerWidth`: «painted into the air the panes' own borders leave, so it is clamped to twice `-border` and invisible when `-border` is 0».

Человек, поставивший `-border 0 -paneDividerWidth 4` и не увидевший ничего, объяснит это из `--help`, не открывая исходников. Это ровно то, чего требовало условие.

## 4. Тест на дефект отступа самостоятелен — проверено мутацией

Тест `render_reference_ut.cpp:1599` `MetalPanes::EachPanesPaddingIsItsOwnBackgroundAndNotItsNeighbours` выставляет `fx.options.paneDividerWidth = 0` (строка 1605) и `setSeams()` не зовёт вовсе — то есть работает на сборке, где шва нет ни в каком виде.

Самостоятельность проверил **мутацией M-B**: выключил проход заливки панели в `render_metal.mm:923-926`, **не трогая отрисовку швов**. Результат:

```
rightPadding == rightBackground failed, at render_reference_ut.cpp:1661
- MetalPanes::EachPanesPaddingIsItsOwnBackgroundAndNotItsNeighbours
OK: 935, ERR: 1
```

Три вещи разом:

1. тест краснеет **при нулевой толщине разделителя** — значит читает дефект, а не работу над швом;
2. краснеет на утверждении о **правом** отступе, то есть на самом дефекте, а не на положительном контроле (левый отступ, который был правильным всегда, — он в тесте есть и на мутации остаётся зелёным);
3. краснеет **он один**: все тесты про шов на этой мутации зелёные, что и доказывает независимость в обратную сторону.
